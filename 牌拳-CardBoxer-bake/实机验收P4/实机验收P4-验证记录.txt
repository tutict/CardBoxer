一、结论（先看这段）
----------------------------------------------------------------
P4 落盘态在真实自动对局里跑通了，没有引入可见抖动：

  * 两次独立 Godot 进程各打完三回，paused 全程 false，
    rc=0、无脚本错误、最终 round_phase 为 over。
  * 3D 开态 128 采样点 / 24 张整帧（sha 全不同）/ 87 张 SubViewport；
    默认关 128 采样点 / 25 张整帧（sha 全不同）。
  * 引擎读回的逐行表标记与 13 骨 delta，与 P4 落地表零失配；
    14 个受监控文件跑前跑后 sha256 全同。
  * 真实对局片段的精确平台 玩家 81→72、对手 83→74；
    最大跳变 玩家 13.661→13.642°、对手 14.662→14.634°（反而略降）。
  * 实机最大 |P4−P3| 逐帧差 1.653096°，在两版表全量 284 帧独立
    复算出的静态上界 D_static 1.870037° 之内。

但收益边界同样要说死：可辨平台 玩家 81→81、对手 83→83 **没有下降**。
P4 的扰动只有 ~0.1° 量级，恰好压在 0.1° 可辨阈值附近；看图复核里
两版姿态差异肉眼很弱。本轮证明的是「实机没被改坏」，不是「动作变好看」。


二、为什么必须跑两次真跑
----------------------------------------------------------------
P4 改的是 data/card_motion.json（2D 动作表）。两个真相来源：

  2D 运行时  fighter.gd:1027 → Motion.sample() → CardMotion._pose_at()
            读 res://data/card_motion.json 的 11 关节 + lean
  3D 运行时  rig_driver.gd::_joints_of() 读 motion_input*.json 的 track

关键事实：3D 开态下 fighter.gd::_draw() 在
`if draw_3d_override: _draw_shadow(...); return` 就 early return，
2D 关节表根本不参与绘制；默认关 3D 时 arena.gd 里 motion_3d 是
空字典，2D 关节表才画进画面。

所以只跑 3D 开态等于没验到 P4 真正改动的可见侧。本轮：

  three_d      CARD_BOXER_3D=1 + CARD_BOXER_TAIKOU_BOT=1
  default_off  只开 CARD_BOXER_TAIKOU_BOT=1

两次都是「不冻结 paused、不注入 card/frame、不推进时钟、不覆盖
任何 mapping 或动作表」，让 arena.gd 自己 _tick_taikou() /
_sync_3d_layer() 打完整局三回；探针只每 0.12 s 读回状态并截帧。

四、同源双表复算（analyze_live_p4.py，12/12）
----------------------------------------------------------------
取 three_d 真跑读回的 128 个 (card, frame)，Python 侧分别按
P4 落地表（shipped）与 P3 原表（orig/pre-p4）复算 13 骨 delta。
帧序列同源、只有动作表不同，逐帧 A/B 才成立。

口径先钉死，只有两类判据：
  ① 结构性：帧在表范围内、复算覆盖全行、引擎读回对账、站架 delta
     全 0、SV 重复图由相同 delta 解释、阶段时长在规格内；
  ② 可复算上界：D_static = 两版表全量 284 帧上 |P4−P3| 的最大逐骨差
     = 1.870037° @wave:34（实机帧是其子集，必然 ≤）。
连续帧跳变首次在 P4 语境量化，**没有历史外部锚，不设放行线**，
只如实报告分布；不拿它当「通过」或「不通过」的线。

  指标（相邻采样点，127 对）       P3 → P4
  精确平台 玩家（<1e-6°）          81 → 72（−9）
  精确平台 对手                    83 → 74（−9）
  可辨平台 玩家（<0.1°）           81 → 81（不变）
  可辨平台 对手                    83 → 83（不变）
  最大跳变 玩家                    13.661424 → 13.642214°
  最大跳变 对手                    14.662057 → 14.633549°
  实机最大 |P4−P3|                 1.653096°（上界 1.870037°）

  逐对额外跳变 P4−P3（度）      玩家            对手
  max                            +0.726887       +0.893446
  min                            −1.287525       −0.401707
  p95                            +0.0621         +0.0621
  mean                           +0.011393       +0.013620

  * 最大跳变两侧都略降，没有出现「P4 把腿甩得更快」的尖峰。
  * SV 87 张归成 34 组（最大组 34 张），同 sha 组内 13 骨 delta
    签名全部一致 → 重复图是数值平台造成的，不是停滞帧缓冲假卡顿。
  * 站架帧两版 delta 全 0；归零残差与阶段时长（含 hitstop 0.24、
    第 1 回 discard 排除 intro）零违规。

注意口径差异：静态 P4 的「精确平台 255→0」是 284 帧**相邻帧**；
这里是 0.12 s 采样点**相邻采样点**，跨帧且只覆盖真实对局用到的姿态。
两者不是同一个数，不能互相折算。

七、本轮踩到并钉死的坑（可复用）
----------------------------------------------------------------
1. **实机验收必须按显示状态分叉**：改 2D 表却只跑 3D 开态，看不到
   被改的那一侧。默认关时 motion_3d 是空字典，探针读 mapping 要防御。
2. **跨进程牌局不可逐像素 A/B**：两次真跑终局 HP 85:80 / 97:63，
   前提不成立就明确记 framewise_pixel_ab_applicable=False，降级为
   同源帧序列公式复算，不硬比、不折进判据计数。
3. **图表纵轴会吞掉要展示的信号**（P4 静态板已踩过，本轮第二次）：
   差异 0.1° 在 10° 主图上等于不存在，必须给独立纵轴。
4. **放大段要按时间连续性分组**：同名招式跨回合会串成假趋势，
   且 x 轴标签别把采样 idx 当帧号。
5. **源码形状判据只扫可执行行**：注释满足裸子串会真空通过；
   本轮 M25 把 await 注释化，判据确实报红。
6. **变异 needle 一律单行 ASCII bytes**：Windows write_text 把 JSON
   报告落成 CRLF，多行 needle 会命中 0 次静默变 DNR；本轮 33 组零 DNR。
7. **守卫子进程禁写字节码**（PYTHONDONTWRITEBYTECODE=1）：避免同秒
   同 size 的陈旧 pyc 被导入，导致变异体其实没执行却报 CAUGHT。


八、历史守卫债
----------------------------------------------------------------
本轮**不改任何游戏源码 / 数据 / 资产**，只往游戏工程 tests/ 新增了
一个探针文件 p4_live_probe.gd（不在 14 个受监控文件清单内）。
跑前跑后 14 个文件 sha256 全同（data/sha_baseline.json 与
data/live_p4.json 的 sha_before / sha_after 双重留证），因此 P1 / P2 /
B / P3 历史 verify 的红因数与 P4 收口时相同，按约定只列债、未重跑、
未改历史脚本、未放宽任何阈值。

十、未决边界
----------------------------------------------------------------
* 观感收益有限：可辨平台不变，看图两版差异肉眼很弱。本轮证明的是
  「真实对局里没被改坏」，不是「动作明显变好看」。
* 3D 开态没做「2D 像素 A/B」——前提不成立（fighter.gd 早退）；
  2D 侧只在默认关看了整帧健康度，没有逐帧位移的像素对照。
* 没有跨进程逐像素 A/B，也没有重跑 B 路线的 cap3 / cap9 A/B；
  本轮只验 P4 落盘态。
* 默认关与 3D 开态是两次独立进程、牌局不同，两行整帧只各自看
  画面健康度，不做同一时刻的对照。
* `#53`（可变形 .blend 的下一步方向）仍 pending。
