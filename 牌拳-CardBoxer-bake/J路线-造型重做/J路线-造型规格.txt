结论：I 路线的 `canvas_item` tint 只把颜色拉成「亮银 vs 暗棕」，
没有动剪影。要根治必须换掉造型部件，重做几何或至少重绘 UV 图案。
这不是渲染 bug，改灯/材质/Shader 都解决不了。

3. 可复算验收判据（最终引擎内截帧，不写死阈值来源）
====================================================================

| 编号 | 判据 | 口径 |
|---|---|---|
| J-01 | 敌我剪影可分 | 同相机同尺度正视剪影 IoU ≤ 0.60，或肩宽/身高差 ≥ 0.15 |
| J-02 | 白衫下摆消失 | 对手角色掩膜内近白像素（RGB 均 > 200）占比 ≤ 2% |
| J-03 | 青云纹消失 | 对手角色掩膜内青色特征像素占比 ≤ 0.5% |
| J-04 | 覆面成立 | 头部 ROI 内不存在红花/双环/长发高饱和暖色团 |
| J-05 | 玩家侧零变化 | 同进程 A/B 玩家 ROI changed_px = 0 |
| J-06 | 可逆 / 零污染 | `CARD_BOXER_FOE_VISUAL=none` 与 H 原样逐像素一致；不设 `CARD_BOXER_3D` 时 `CHANGED_PIXELS=0` |
| J-07 | 驱动链不断 | 13 骨 + skin、72/73 帧可驱动、`motion_input_foe.json` 按新 rest 重建 |
| J-08 | 全量回归 | 15 套引擎内自检全绿 |

口径说明：J-02/J-03 的基线来自 data/texture_pair_j.json 的
`near_white_ratio_512` / `cyan_ratio_512`（贴图级）与 I 路线
data/visual_diag_i.json 的角色掩膜口径（渲染级），两者不可混用。

4. 三条候选链与成本账（先算账再动手）
====================================================================

| 链 | 做法 | 代价 | 主要风险 |
|---|---|---|---|
| J1 重生成 3D | 用 2D 概念图重跑 image-to-3D，prompt 明确禁白衫/云纹/头冠 | 生成 1 次 3~5 分钟（**有每日配额 5/5 限制**）＋ Voxel 连续壳、13 骨权重、SURFACE_DEFORM、GLB 导出、rest 重建、Godot 导入、A/B 全链 | 生成结果不可控，可能又带 V4b 元素；配额可能已被占满 |
| J2 壳级剪影手术 | 在现有高模上按连通壳空间位置删除白衫/披风/头冠，补程序化覆面头盔与工业围裙，再重跑绑定链 | 不需要生成服务 / 不需要配额；但要重跑 Voxel+绑骨+导出+rest | 删顶点会破坏 SURFACE_DEFORM 顶点索引；新部件 UV/材质要另开槽 |
| J3 只重绘 UV 图案 | 把 foe baseColor 里的白衫/云纹/头冠区域改画成警示涂装 | **零绑定链重跑**，最快 | 剪影不变（下摆/披风/头冠形状还在），只能算半根治 |

工程师选 A 时要的是「根治同源观感」，J3 不满足 J-01。
优先 J2（可控、可复算、不依赖配额）；J1 作为生成配额可用时的
造型来源备选。任何一条都必须保留 I 路线已验收的
玩家侧零变化 / off 开关 / 默认关零污染三条性质。

6. 订正（2026-11-12 r2，实证推翻 §0 的依据与 §4 的优先链）
====================================================================
本节不删原文：§0/§4 是动手前的判断，作为负结果原样留档。以下为
r1 手术失败 + 回滚后重新量出来的事实。

6.1 §0 第 16 行「造型层真同源」的依据用错了图
  * `shots/asset_v1/j-sv-foe.png` 是**未经 canvas tint 的 SubViewport
    原图**，不是玩家最终看到的合成帧。
  * foe baseColor 4096² 实测（diag_motif_j.py，1024² 分析）：
    near_white = **0.0%**、cyan = 0.1405%、hot_red = 0.001%；
    player 近白 14.98%、青 1.66%。foe 贴图里根本没有白色布。
  * 但 v1 SubViewport 原图的 foe 角色掩膜内 near_white = **20.86%**
    （比 player 的 17.04% 还高）。这多出来的白不是贴图，是
    I 路线 `data/rootcause_i.json` 已经证实的渲染链：
    四盏高强方向灯 + `metallic=1.0` 抑制 albedo 漫反射，
    镜面高光把暗灰照白；贴图 70.99 的亮度差被吃成渲染 -11.18。
  * 所以「白衫下摆 + 青云纹」在**最终合成帧**里已被 I 路线 tint
    (`vec3(0.42,0.30,0.28)`) 清零：C0 掩膜 near_white = 0.0%、
    cyan = 0.0%（probe_recolor_j.py）。§3 的 J-02 / J-03 判据
    在动手前就已满足，不能再当作「根治」的证据。

6.2 真正剩下的同源是「几何部件」，不是颜色
  * 看 `boards/J-语义重绘探针.png`：C0/C1/C2 三档角色掩膜像素数
    逐档完全相同（71,959），白衫下摆的长条形状、左侧黑披风、
    头顶青冠/红花形状、站姿一个都没变。
  * 2D canvas 层无论怎么调色都改不了剪影；改 3D 材质/灯又会串扰
    玩家侧（I 路线 `player_leak_i.json`：玩家 ROI 变化 23.78%）。
  * 改 baseColor 贴图同样不对症：metallic=1.0 + 强灯下 albedo
    基本不参与成像。

6.3 r1 壳级手术（J2）已证伪并回滚
  * `build_foe_shape_j.py` 对 2,809 个连通壳按 bbox/质心粗分类，
    对 SKIRT/CAPE/HEAD_TOP 做「顶点压缩 + UV 打补丁」。
  * 结构 invariants 全过（64,024 顶点 / 79,998 面 / 1 UV /
    1 材质 / 64,006 权重顶点，前后逐项相同），但看图
    `shots/asset_probe/j-sv-foe.png`：黑披风被拉成一堆白色尖刺碎片，
    白衫下摆、青云纹、青结晶头冠、红花**一个都没消掉**。
  * 根因：① 压缩顶点只变形不删除，薄壳被拉成针状面；
    ② 按 bbox 粗分类无法对应「青云纹/红花」这类语义部件，
    而青云纹本质是贴图图案，几何手术碰不到；
    ③ UV 补丁只覆盖 `p.vertices[0]` 命中的面。
  * 已用 `rollback_shape_j.py` 逐字节还原工程 GLB 到 I 基线
    0edcfe9e…（6/6 校验通过），失败产物/截帧/报告全部留在 J 目录。

6.4 修订后的候选链（成本账，等工程师定方向）
  | 链 | 能不能改剪影 | 代价 | 主要风险 |
  |---|---|---|---|
  | A 表现层语义重绘（C2 警示条纹） | 否 | shader 常量 + A/B + 变异；零资产改动 | 只是观感改善，不叫根治 |
  | B 精确删壳 + 重导 GLB | 是 | 按 UV 岛精确定位目标壳 → 顶点塌缩到质心（不撕面）→ 重导 GLB + Godot 导入 | 分类精度仍需实证；补覆面头盔/围裙要新几何 |
  | C 重生成 3D（J1） | 是 | 生成 1 次 + Voxel/13 骨/SURFACE_DEFORM/GLB/rest/Godot 全链 | 每日配额 5 次、结果不可控、可能又带 V4b 元素 |
  | D 维持现状归档 | 否 | 0 | 同源观感留存 |

  备注：J-01 口径也需订正。diag_motif_j.py 实测两侧
  bbox 归一化外接框 IoU 上界 = 0.90236、肩宽/身高差 = 0.06792，
  两条都不满足 §3 的 ≤0.60 / ≥0.15。即剪影本来就相近，
  §4 写「J3 不满足 J-01」这点成立，但 J2 同样没做到。
