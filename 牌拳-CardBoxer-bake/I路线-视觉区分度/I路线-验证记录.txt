====================================================================

工程师选 A：修 H 路线遗留的「双方 3D 侧面战斗里两人看起来太像」。

**视觉区分度做成了，但只做成表现层这一半**：

- 同进程同树 A/B 硬证据：视觉开时对手角色整体压成暗锈褐、轮廓加宽压矮；
  玩家侧 ROI **0 / 33390 px 变化**（逐像素不变）。
- 亮度差从 H 基线的 -11.18（方向还反了）翻到 **+54.36**，
  对手亮度掉 68.74，红蓝偏移差 -8.83，宽 ROI 轮廓比 1.1259。
- 可逆开关 `CARD_BOXER_FOE_VISUAL=none` 实测有牙：off 态与还原态

  15 套引擎内自检 15/15 ALL GREEN。

  `arena.gd`、`fighter.gd` sha256 与 H 基线逐项相同；
  **既有源码只改了 `scripts/fighter_3d_layer.gd` 一个文件**。

**没做成的那半要明说**：两人的**造型语言仍然同源**——同一套

不同设计的角色。重做造型要重跑 Voxel / 绑骨 / GLB / rest 全链，
本轮按规格明确不碰 3D 模型。

2. 根因：不是贴图，是渲染链
====================================================================

诊断顺序（每一步都先证伪上一个假设，证据在 data/）：

| 步骤 | 量到的东西 | 结论 |
|---|---|---|
| texture_i.json | 两张 4096² baseColor 的 UV 岛亮度 104.53 / 33.54，差 **70.99**；近黑填充差 3.1% | 贴图本身足够暗，「黑填充稀释」被证伪 |
| rootcause_i.json | 同进程单角色渲染亮度 玩家 95.02 / 对手 106.2，差 **-11.18**（反了） | 70.99 的差被渲染吃光 |
| material_i.json | 两侧都 StandardMaterial3D、metallic/roughness 乘数都 1.0、都挂 metallic texture | 材质配置同构，不是某一侧少了贴图 |
| 判定 | 四盏固定方向高强度灯 + metallic 1.0 抑制 albedo 漫反射 | **渲染链问题，不是贴图也不是拓扑** |

所以决策是改表现层，不重做模型。

却仍有像素变化，就是这个串扰的定量证据。

r1 的处理按项目规矩**不放宽阈值**：spec 目标仍钉 1.1，
把实现从 1.16 提到 1.22 后重跑 A/B 实测 1.1259。
`verify_i.py` 的 `spec_width_target_not_relaxed` /
`r1_negative_result_kept_false` 两条判据专门钉这两件事。

7. 验收与变异
====================================================================

- `verify_i.py` 57 条承重判据，全部从盘上重算（源码文本、逐文件
  sha256、各 JSON 的 checks 与数值、负结果 ok=false、清单逐条 sha）。

  `CHECK <点名判据> False` 出现在输出里，否则算 MISSED——避免
  「清单 sha 顺带变红」冒充针对性守卫有牙。
  变异覆盖：源码 scale / tint / 退役常量回归 / off 开关改名、
  spec 目标放宽、r1 负结果翻转、A/B 与 off 判据翻转、15 套自检结果、
  静态 A/B 像素、基线 sha 篡改、final 报告 ok 翻转。
- 守卫子进程带 `PYTHONDONTWRITEBYTECODE=1`：CPython 时间戳 pyc
  只对照整数秒 mtime + size，快 runner 上多组变异可能落在同一秒，
  不禁写会读到上一例陈旧字节码、误报 `GREEN (MISSED!)`。
- `selftest_did_not_run_i.py` 故意把 M01 锚点改成不存在的串，证明
  `DID NOT RUN` 分支有牙：8/8，汇总如实 `MUTATION_I_FAILED`。
- 还原一律二进制写回 + sha256 比对，不用文本读写（换行会被转）。

8. 踩坑（本轮新增，可复用）
====================================================================

1. **报告 ok=false 可能是「应用瞬间」的中间态**：`patch_visual_v3_i.json`
   一开始 `no_3d_material_duplicate=False`，幂等重跑后 12/12 全绿——
   源码后来被清理过，报告没重算。判据必须能按盘上源码复算，
   不能把一次性的应用报告当永久结论。
2. **按连续字面量扫跨行写法会漏**：`off_switch_present` 第一版钉
   `OS.get_environment("CARD_BOXER_FOE_VISUAL")`，源码里其实是
   `OS.get_environment(\n  "CARD_BOXER_FOE_VISUAL")` 跨行，误报红。
   改成钉「名字 + none 判别 + 仅 foe 分支」三个形状。
3. **Godot 4.4+ 会自动生成 `.gd.uid`**：按文件名白名单卡「工程新增
   文件」会误报；改按形状放行 `tests/*_probe.gd` 与配套 `.gd.uid`。
4. **窄 ROI 会造出恒 1.0000 的假指标**：加宽角色被 128 px 窗口裁断，
   宽度比看着像「完全没变」。必须按被测形状换度量窗口，不能改阈值。
5. **退役常量与过期注释是债**：v1/v2 的 3D tint / metallic / 灯能量
   常量留在源码里，注释还写着「运行时 tint 只在副本上做」，与定稿
   实现相反。final 补丁一并清掉，并由 `source_retired_constants_absent`
   钉住不许回来。

9. 边界（明说没做的）
====================================================================

- 没重做对手怪造型、没改 GLB / UV / PBR / 骨架 / 228 帧动作表；
  两人轮廓与服装语言仍同源，只是颜色与尺寸分开。

- 3D 层默认仍由 `CARD_BOXER_3D` 关着；I 的视觉层只在 3D 开且
  `configure("foe")` 时生效，没把 3D 做成默认或设置项。
- 没测 3D 开时的 GPU skin 成本；H 路线遗留的「双侧 prims
  1,104,816 ≠ 两个单侧之和」口径异常本轮未解释。
- 没导可执行包，没做真机 / 移动端验证；产物是 Godot 工程内运行时接线。
