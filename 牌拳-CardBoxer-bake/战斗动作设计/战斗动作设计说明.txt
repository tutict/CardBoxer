《牌拳》回合制（太阁合战）战斗动作设计说明
================================================================
日期：2026-11-08
需求：工程师「接下来就是设计战斗动作」
状态：**规格层设计完成；游戏源码 0 改动、未烘新帧、未导 Godot**


一、结论（先给）
----------------------------------------------------------------
  1. 现状**不是「没有动作」**，而是「动作与胜负脱钩」：回合制一直在播
     实时格斗时代那 228 帧，但 `arena.gd:652-655` 只把「亮出的 3 张牌里
     的第 1 张」交给 `perform_visual()` 当纯表演。赢家可能在播「后撤」，
     输家可能在播「气功波」—— 玩家看动作完全读不出谁赢了。
  2. 真正的卡点不是造型，是**语义与节奏**：亮牌阶段就不该打架；
     伤害在 `_resolve_taikou()` 才结算，攻击动作却提前在 reveal 播完了。
  3. 本轮交付「事件表 + 牌型绑定 + 伤害分档 + 时间线 + 资产计划」，
     一份机器可读 `battle_motion_spec.json` + 判据，不改任何 `.gd`。
  4. **new 资产一律没烘**。上一轮刚证明对手怪 3D 骨架 35° 驱动下右臂
     不可见，所以 P0 接线只允许用现有 7 项 reuse 资产。规格不假装已有。

  resolve 播完还剩 1.64 s **站桩空转**。


三、五个缺口 → 规格怎么补
----------------------------------------------------------------
  G1 只播 3 张亮牌的第 1 张，且与胜负无关
     -> P2/P3 + card_type_binding，动作由牌型决定
  G2 赢家/输家动作与判定结果无关
     -> reveal 只做仪式；赢家攻击只在 resolve 的 0.12~0.72 s
  G3 阶段时长大面积空转
     -> events 用「起势 / 亮牌 / 定格 / 收势 / 回站架」显式占满
  G4 四种伤害共用 0.26 s hit_light
     -> damage_tiers 三档 + draw 档，复用 fighter.gd 已有硬直四档
  G5 弃牌 / 选牌 / EX / 三回结束 / 局结束 / KO 全靠 HUD 文字
     -> events 与 outcomes 全覆盖


四、设计原则
----------------------------------------------------------------
  P1 亮牌阶段不打架：同时亮牌 → 比牌型 → 结算，与太阁 IV 同构。
  P2 动作强度由牌型决定，不由第一张手牌 id 决定。
  P3 输赢决定谁播攻击、谁播受击；平局双方对峙后各吃一下。
  P4 EX 独立分支，蓄力 + 爆发两段，不能只换 HUD 文字。
  P5 动作时长落在阶段内，播完定格，不留站桩。
  P6 reuse 与 new 分开标注，new 不得假装已有。

六、牌型 → 动作强度绑定
----------------------------------------------------------------
  牌型       赢家动作           帧数   输家反应        extra    硬直

七、伤害档（由 taikou_rules.damage_of 对 165 组 rank 多重集复算）
----------------------------------------------------------------
  triple   14 + sum/3 -> 15..23
  sequence 10 + sum/3 -> 12..18
  scatter   5 + sum/3 ->  6..13
  draw     固定 3
  档位之间数值有重叠（如 12..13），所以**按牌型分档，不按伤害数值分档**
  —— 这是刻意的：牌型是玩家看得懂的语义，伤害点数不是。
  判据会逐组复算并核对这三个区间，防止写死数字过期。


八、EX 与结局
----------------------------------------------------------------
  EX：`Rage.is_full` 且本回消耗怒火升 EX 时，该侧播 ex.charge +
      ex.burst；rank 由 `Rage.best` 升级，升级未被采用则 `ex_boosted=false`
      不播爆发。EX 只改牌型与表现，不改伤害公式。
  结局：局胜 / 局负 / 平局 / KO / 三回战罢，全部在 outcomes 里点名动作；
      现状这五种都是 HUD 横幅，角色一动不动。


九、资产计划：reuse 7 项 / new 10 项
----------------------------------------------------------------
  reuse（现在就能用）：stance、focus、jab、cross、wave、
      hit_light、hit_heavy
  new（尚未烘）：reveal_ready / reveal_present / reveal_hold /
      ex_charge / ex_burst / hit_crush / round_victory / round_defeat /
      round_settle / ko_fall
  **阻塞**：对手怪 3D 模型在 35° 驱动下右臂不可见（见
  `拓扑修复探针V1/拓扑修复探针-结论.txt` 第三节），骨架可用性未证；
  且现有 228 帧是按实时判定帧烘的，回合制没有判定帧，
  `CardMotion.sample()` 的 phase/progress 要按阶段时间重新映射。
  所以 P0 接线只用 reuse + 现有 `fighter.gd` 播放器，new 留 P1。
