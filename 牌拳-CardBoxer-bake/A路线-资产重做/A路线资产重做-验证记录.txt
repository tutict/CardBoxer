3. 两条可行性探针与选定理由
====================================================================
A1 · Voxel 连续壳 + Smart UV + Blender 贴图烘焙（probe_bake.py）
  切 CYCLES 后 512² / 8 samples 烘焙成功，耗时 0.5s；
  a1-bake-probe.png 378,229 B，亮度标准差 13.69（非空白）。
  但 use_selected_to_active=False：它只证明「本机烘焙 API 能跑」，
  没有把原贴图转移到新壳上。且 smart_uv_poll=False 会让 Smart UV 链
  在 headless 下多一道风险。
  → 判据 A-05 / A-06 / A-07 把这条「半可行」如实钉住，不冒充贴图转移。

A2 · Voxel 连续壳 + 13 骨 + SURFACE_DEFORM 绑定原高模（probe_surfdeform.py）
  voxel_size=0.020：2,809 壳 → 3 壳 / 20,204 顶点；
  ARMATURE_AUTO 覆盖 20,196/20,204 = 99.96%；
  bind 成功、is_bound=True、rest_drift=1.92e-06 m；
  原高模 UV 1 层 / 1 材质 / 3 张 4096² PBR 逐项不变；
  4 张探针图（jab06 / cross10 / wave17 / rest / 55° 侧视）有效；
  整条探针 3.89s。
  → 选 A2。理由：唯一不需要重烘 UV/PBR 的链路，原资产视觉零损失；
    代价只是多一个 20k 顶点的代理壳和一份 bind 数据。
