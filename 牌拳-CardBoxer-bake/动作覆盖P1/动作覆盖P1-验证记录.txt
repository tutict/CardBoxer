二、P1 前诊断（证据：../动作优化诊断/）

  一回总时长 3.4 s = reveal 1.5 + resolve 1.9
  赢家播动作窗口 ATTACK_S = 1.12 s，占 32.94%
  输家 / 平局 / 亮牌阶段 3D 侧 0 s，全程 stance
  3D motion_input.json 只有 jab 14 / cross 22 / wave 36 = 72 帧
  2D card_motion.json 有 12 卡 228 帧 + 3 受击轨道 56 帧 = 284 帧
  覆盖率 72/228 = 31.58%，受击轨道 0
  fighter_3d_layer.gd::apply() 白名单只认三卡，其余全退 stance
  每动作只动一条手臂；腿骨被 leg_cap_deg=3 限到 ±3°

诊断结论：问题是「几乎没有动作」而不是「动作不好看」；扩表是纯数据转换。
诊断脚本自身也订正过两处口径：白名单只在 apply() 函数体内扫（否则把兜底
stance 算进白名单导致假红），以及「ATTACK_S 结束硬跳 stance」假设不成立
（末帧最大残差 1.42°，snap_back_visible=false）。历史注释写的「73 帧」
也已订正为 14+22+36=72 帧。

五、接线层（只改表现层）

  fighter_3d_layer.gd::apply()
    旧：if c != "jab" and c != "cross" and c != "wave": c = "stance"
    新：if c != "stance" and not motion["cards"].has(c): c = "stance"
    白名单由数据决定，以后加轨道不必再改源码；stance 仍是兜底值，
    本身不在 cards 里。World3D 修复轮的 sv.own_world_3d = true 原样保留。

  arena.gd（改动全部夹在 _sync_3d_layer 区块内）
    reveal：两侧同播 focus，帧号 = _3d_frame_of("focus",
            tk_phase_time / REVEAL_S)，REVEAL_S=1.5 与 _tick_taikou()
            的 reveal 判定同值，只用于映射进度，不改阶段时长。
    resolve 赢家攻击：G/H 路线原逻辑一字未改（承重判据用「忽略缩进逐行
            比较」把备份里的攻击块钉在当前 sync 体内）。
    输家 / 平局：按 hit_light / hit_heavy 播受击；命中时刻 HIT_AT_S
            之后起播，用四档硬直时长归一化，播完自然回 stance；平局
            不启节奏时钟，用 tk_phase_time 从 0 起播，两侧同播。
    四档硬直表 REACT_STUN_TILT / REACT_DURATION_S 与 fighter.gd 的
            _stun_tilt / _stun_duration 同口径（"" 0.55/0.26、
            launch 0.9/0.42、stagger 0.7/0.5、super 1.2/0.75），
            阈值 abs >= 0.6 也与 fighter.gd:1050 一致。判据从两份源码
            现场解析数值对账，任何一侧漂移都会红。
    hit_crush 不自造：spec 里只是规格索引，2D 侧 super 实际走 hit_heavy，
            3D 跟它一致；block 轨道烘进表备用（回合制不进 BLOCKSTUN）。

  修过的坑：Dictionary.has() 返回 Variant，用 := 推断会触发 GDScript
  Parse Error，导致 battle_motion_p0_check / battle_rhythm_check /
  redraw_gate_check 180 s 超时。改为显式 `var has_focus: bool` /
  `var has_react: bool` 后 15/15 恢复全绿。承重判据专门钉了这两个显式类型。

十、本轮订正的归档债与边界

  1) logs/arena.diff 原先是修 GDScript Parse Error 之前的版本（里面还是
     `var has_focus :=`）；本轮用当前源码重新生成，现在能读到
     `var has_focus: bool` / `var has_react: bool`。layer.diff 同步刷新。
  2) 此前口头写的「MOTION_P1_PROBE_OK 24/24」少算一条；以
     logs/probe.out 与 data/motion_p1_probe.json 为准，是 25 条 CHECK 全 True。
  3) 本机 `binaries/python/3.13.12` 没有 Pillow，verify / probe / board
     脚本必须用项目 venv（3.12.14 / Pillow 12.3.0）；用错解释器会在
     import 阶段就挂，不是判据红。这是项目日志里已记过的坑，本轮复踩一次。
  4) make_filelist.py 首版 all_sizes_positive 假红：shell 先把 stdout 重定向
     到 logs/filelist.out，Python 枚举时该文件还是 0 字节（自引用竞态，
     与上一轮记过的坑同源）。修法：按名排除这个自引用输出日志，并新增
     enumeration_complete 断言「清单集合 == 原始集合 - 清单自身 - 自引用日志」，
     防止顺手把证据文件一起漏掉。同时修掉「失败时仍打印 FILELIST_OK」的
     撒谎标签，改为 FILELIST_FAILED + 逐条 FAIL + 退出码 1。
     终值 FILELIST_OK；文件数与总字节以 `文件清单.txt` 首部为准
     （清单生成时排除自身，写死数字会在下一轮变成过期债）。
  5) 本轮只补承重判据、变异、自检重跑与归档，没有再改游戏源码、GLB、
     贴图、project.godot；源码 sha 在变异前后逐字节不变。
  6) 未解决 / 未做：动作仍是 2D 关节表 retarget 到 3D 骨架，腿骨被
     leg_cap_deg=3 限幅，所以视觉上仍偏「上半身动作」；两条手臂仍不会在
     同一招里同时大幅动。这属于动作表现质量（P2），不是覆盖率缺口。
     #53「可变形 .blend 的下一步方向」仍 pending。
