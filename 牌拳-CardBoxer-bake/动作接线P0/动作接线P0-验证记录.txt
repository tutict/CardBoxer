五、本轮踩到并订正的四个坑（可复用）
────────────────────────────────────────────────────────────
① **截帧成功判据假绿**：只查 "SCRIPT ERROR" 会漏掉引擎 stderr 里的
   `ERROR: String formatting error`。首版 4 张图照样存下来、rc=0，
   但 [P0_SHOT] 打印的是未格式化的 `%s` 模板。改成查 stderr 段的
   `ERROR:` / `Parse Error`，并钉 marker 必须含预期 motion/label/hp。
   与之前「守卫钉形态不钉词」是同一类问题。
② **GDScript print 的占位符与参数必须严格等量**：多传 1 个报
   "not all arguments converted"，`%d` 接 float 报 "a number is required"。
   统一改 `%s + str()`，不靠猜类型。
③ **裸子串计数会被自己的注释骗**：V13 数 `Rules.damage_of(` 得 3
   （2 次真调用 + 1 次注释）。改钉完整赋值形态
   `tk_damage = Rules.damage_of(tk_player_result)` 并与备份独立复算。
④ **变异脚本里中文路径不能写成 bytes 字面量**（SyntaxError:
   bytes can only contain ASCII literal characters）。整文件替换型的
   源路径改用 str，运行时再判 isinstance。与前几轮记的
   「needle 只能 ASCII」是同一条规矩的延伸。

六、边界（没做的部分）
────────────────────────────────────────────────────────────
* spec 里 asset_plan.new 的 10 项（reveal_ready / reveal_present /
  reveal_hold / ex_charge / ex_burst / hit_crush / round_victory /
  round_defeat / round_settle / ko_fall）**一项都没烘**。
  hit_crush 在代码里只是规格索引字符串；实际受击由 extra="super"
  触发 fighter.gd 的 0.75s 硬直 + 已烘 hit_heavy 轨道。
* 亮牌阶段播的是 focus 起势，不是「按牌型分三档的亮牌定格」；
  EX 仍只有牌型升级 + HUD 角标，没有蓄力/爆发动作。这两块是 P1/P2。
* 三回制、怒火槽、伤害公式、实时模式兜底（BATTLE_MODE 仍是
  "taikou"）、2D 外观层全部未动；游戏内角色仍是 GDScript 自绘，
  没有接任何 3D 模型 / 精灵图集。
* 5 张「引擎帧」是注入确定性牌型后的**引擎内渲染**，不是真人操作录屏；
  注入块临时写 arena.gd，finally 逐字节还原并用 sha256 证明
  （RESTORE OK sha256=5c4c393b…）。
* 18 条判据一条都没评「动作好不好看」；看图结论只有一句：
  五种状态的 banner / 亮牌框 / 血条 / 角色姿势都能分辨，无空白或截断。
* 本轮改了游戏源码，因此前面几轮「游戏源码 0 改动」的结论不再适用。
