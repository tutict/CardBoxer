4. 双轨开关与动作同步
========================================================================
  · `arena.gd:52`  `var use_3d := false`；`arena.gd:219`
    `use_3d = OS.get_environment("CARD_BOXER_3D") != ""`。
    环境变量非空才建层，失败则 `remove_child + queue_free`，
    不会留下半初始化的 3D 节点。
  · `fighter.gd:564` `var draw_3d_override := false`，
    `_draw()` 里先判它再决定要不要画 2D 自绘；默认 false。
  · `_sync_3d_layer()`：层的位置 = `player.position + player.visual_shift`
    （沿用 P0 节奏的位移，判定坐标不变）；只有「玩家赢下本回 +
    节奏时钟激活 + 有赢家动作 + 在 ATTACK_S 窗口内」才播攻击，
    其余（输家 / 平局 / 亮牌阶段）一律 `stance`——73 帧表里没有
    受击轨道，硬凑会变成自造动作。
  · `fighter_3d_layer.gd` 明确只画：不写 position / HP / 伤害 /
    牌型 / 硬直 / 阶段时长；`A13_layer_no_gameplay_writes=True`。
  · 贴图：`DRAW_SCALE=0.45`、`DRAW_OFFSET_Y=18.0`，把 3D 脚底
    对齐 2D 擂台地面；水平镜像用**负宽度 Rect2**，不用
    `draw_set_transform`（后者会吃掉 arena 设的 position）。

5. 侧面战斗（本轮硬要求）
========================================================================
诊断：`use_3d` 之前 3D 层是 F 路线的正视 A-pose，出拳像摆臂；
"侧面战斗"落点应该是相机朝向 + 站架，而不是改动作表。

  · 相机：`_place_camera()` 用 `CAM_RADIUS=3.55`、
    `position = (R*sin(yaw), 1.12, R*cos(yaw))`，
    `look_at(0, 0.86, 0)`，FOV 33°。`DEFAULT_SIDE_YAW := 55.0`。
    **不用 90°**：D 路线实测零厚度披风壳退化成一条细线，且骨架
    动作平面 (XY) 与视线平行会把出拳幅度压成 0；
    `A07_no_90deg_view=True` 钉住源码里不存在 90° 视角。
  · 八宫格 `run_side_view_probe.py`：yaw 0 / -35 / -55 / +35 / +55
    与 flip 组合共 8 视图、8/8 截帧 1280×720、0 error、
    `view_changes=8`、`bones=13`、final=55.0/False。看图定稿
    `yp55-f0`：相机在左前方、脸朝画面右，正对右侧 2D 对手，
    披风/发髻/护腕都有侧面厚度，没有退化成线。
  · 站架：四档对照 `run_side_stance_probe.py`（none / light /
    mid / heavy，固定 yaw=55°）+ 六组反向扫描
    `run_side_stance_scan.py`（r0-flip-all / r1-flip-fore /
    r2-flip-upper / r3-fonly-neg / r4-both-neg /
    r5-guard-high）。看图选 `r0-flip-all`：
    双拳收到胸前护脸、前后脚分开、双脚贴地、无撕裂。
  · 定稿偏置（度，绕 Z，与 rig_driver 的 delta 同符号口径）：
        upperarm_f  26.0    forearm_f -50.0
        upperarm_b -26.0    forearm_b  50.0
        spine        4.0    head       -2.4
        thigh_f     10.0    shin_f     -6.0
        thigh_b    -12.0    shin_b      7.0
    `A08_stance_bias_exact` 逐值钉死，`A09` 钉默认值被应用，
    `A10` 钉它只是后处理，`A11` 钉实现走
    `get_bone_pose_rotation → 乘四元数 → set_bone_pose_rotation`，
    而不是改公式或烘进表。`CARD_BOXER_3D_STANCE=none` 可退回
    F 原样 A-pose，专供 A/B 取证，不是生产默认。

诚实边界：`view_flip` 有开关但默认 false，层里**没有按 facing
自动镜像**；对手侧没有 3D 模型（F 只产出玩家侧带 skin 的 GLB）。
所以这是"玩家 3D 侧身对 2D 对手"的混搭画面，
不是 KOF 式双方都侧身、也不是玩法层的朝向翻转。

10. 踩坑清单（可复用）
========================================================================
  ① Godot 每次启动随机化全局 RNG —— 跨进程整帧像素等价不可当判据，
     必须用冻结状态（paused + 隐藏动态子节点）或同进程同树 A/B。
  ② GL Compatibility 下 2D 主场景可挂 3D SubViewport，但
     `transparent_bg=true` + `UPDATE_ALWAYS` 必须显式设；
     截图必须带窗口启动，headless 拿不到有效纹理。
  ③ 90° 侧视会把零厚度披风壳压成线，出拳平面与视线平行后幅度归零，
     3/4 视角（55°）才是这套资产的可行区间。
  ④ 站架偏置不能烘进 motion_input：driver 每帧覆写全部 13 骨，
     只能在 `apply_frame()` 之后逐帧叠加，否则会被冲掉；
     也不能改 driver 公式，否则 F 路线的三重对账全部作废。
  ⑤ 负宽度 Rect2 做水平镜像；`draw_set_transform` 会覆盖节点自身
     transform，把 arena 设的 position 吃掉。
  ⑥ 验证记录 / 清单会进清单 → 不写死条目数，给可复算命令 +
     动态覆盖检查；清单用 `write_bytes` 写，避免 CRLF/LF 假红。
  ⑦ 变异 harness 的"锚点失配"必须计入未证明，并用独立 selftest
     证明这个分支有牙；否则汇总会比没有汇总更坏。
