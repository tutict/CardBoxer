一、结论先行
====================================================================
V2 是「扁平剪影 + 单一平涂」；街霸的核心是**体积 + 卡通二分明暗 +
夸张比例 + 清晰剪影**。V3 按 **Street Fighter IV** 路线重做渲染层与比例，
不复刻 IP：cel shading 三档硬边明暗、粗墨线描边、放大手脚、宽肩缩头、
凶眉鼻影、双臂可见。八帧全部从「纸片人」变成有体积的卡通拳手。

verify_2d5.py **11/11 PASS**（MODEL_2D5_VERIFIED），坐标桥仍成立
（鞋距 157.0 px vs 预测 157.5 px），游戏目录 0 文件改动。

**上限如实说**：这是程序化几何 + 卡通渲染，能到「SF IV 的味道」，
到不了 SF6 的角色精度。SF6 是 RE ENGINE 写实肌肉 + 皮肤细节 + 布料物理
+ 微表情（资料称隆的升龙拳脸有 47 个 blend shape），那是天级美术资产
投入，不是调渲染参数能到的。要真到那个程度得换路线（第七节）。

====================================================================
二、风格定位：为什么选 SF IV 而不是 SF6
====================================================================
 查证结果（2026-11-07 检索）：
  - SF II / III：手绘像素精灵，靠画师逐帧绘制（Akiman / Bengus）
  - **SF IV (2008)**：3D 模型 + 2D 玩法平面 + 卡通渲染 + 水墨（sumi-e）、
    粗描边、夸张厚重的四肢、大手脚
  - SF V (UE4)：风格化写实「可动人偶」
  - SF6 (RE Engine)：写实肌肉 / 皮肤 / 微表情 / 涂鸦街头风

 关键发现：**SF IV 的「夸张大手大脚」不是审美失误，是为让命中判定
 在远距离更可读的功能设计**。这跟《牌拳》「屏幕 x == 判定 x」的正交
 坐标桥是同一套逻辑 —— 我上一轮把拳套从 9 缩到更小其实走反了，
 V3 反而放大到 13 game px。

 所以选 SF IV：它是「3D 体块 + 2D 判定」这条路，和现有 228 帧动作表、
 坐标桥同构，不用推翻任何已验证的东西。

三、V3 技术改造（坐标桥 / 11 关节 / 12 部件 / 8 shot / manifest 全不动）
====================================================================
 1. toon_material()：Diffuse → ShaderToRGB → ColorRamp(CONSTANT 三档)
    → Emission → Output。把光照结果量化成硬边明暗，末端用 Emission
    保证档色就是调色板、不被场景二次打光。
 2. probe_toon.py **先做可行性探针**：单独渲一个球，证明本机的
    Blender 5.2.3 EEVEE headless 确实支持 ShaderToRGB 且颜色被量化
    （主色聚成 2~3 簇而非连续渐变），才动主脚本。
 3. flat_material()：描边 / 五官 / 金扣 / 银环用不受光 Emission，
    墨线在任何角度都是稳定的深色。马甲另用 toon 深色，避免纯黑死板。
 4. ribbon 加 BEVEL 修改器（width 0.011 / 2 段）：平面挤出带有了圆角
    弧面，cel shading 会在窄倒角面落进另一档亮度 —— 体积感从这里来。
 5. 街霸式比例：拳套 9→13 game px、鞋 22×11→30×14 + 金底加厚、
    躯干肩半宽 26→30、头半宽 18.5→16（头小身壮）、描边 3→4 px。
 6. 表情：加凶眉（倒八）、鼻影、略斜的嘴；SF 的脸是「远距离一眼
    读出情绪」，比五官精细度重要。
 7. 双臂可见：护头姿势下后臂的 x 落在躯干宽度内，V2 里被完全遮挡。
    V3 把后臂挪到躯干**前**但用暗一档袖色（sleeve_back），
    用明度编码前后而不是靠遮挡 —— 2D 格斗的常见手法。
 8. 环刃压暗、缩小、后移，从「腰侧发光圈」变成暗色腰饰；
    中国结从小沙漏改成圆结 + 流苏。

四、迭代与两次误判（都靠对象级诊断纠正，不靠连试参数）
====================================================================
 轮次   现象                              实际根因 / 处置
 --------------------------------------------------------------------
 V3-1  cel shading 生效，明暗档出现      探针先行，一次成功
 V3-2  加大手脚/宽肩/凶眉后，jab、      先猜「cel 亮部过曝融白底」，
       throw、hit_heavy 出现两条        把全局亮部档 1.08→0.94，**无变化**
       穿过身体的深色长斜线
 V3-3  再猜「白外套整体太亮」，         仍无变化
       给白外套单独调 bands
 V3-4  **停止猜测，做隔离实验**         diag_pose.py（可指定帧）：
       arm only = 两条水平灰带；
       leg only = 两条裤腿；
       white_outer only = 白梯形 + 两条深色边
       => 斜线就是白外套的左右描边，不是多余物体
       diag_body.py 单变量：主体单独渲可见（浅灰梯形），
       把三档强制染红也可见 => 几何/材质链路都正常
       **真因：材质色是线性值**，线性 0.77 经 Standard
       view transform 编码成 sRGB ≈ 0.89(227)，仍撞纯白背景，
       所以躯干内部看不见、只剩两条墨边像孤立的线。
       修法：白外套三档压到 (0.22, 0.38, 0.54)，亮部
       线性 0.51 → sRGB ≈ 0.74(189)，终于与白底拉开。
 V3-5  躯干成为连续灰白块，斜线读作轮廓  11/11 PASS

 这已经是第二次踩「白部件融进白背景」：V2 是白外套与白底同色，
 V3 是线性色经 sRGB 编码后又撞白底。**同色消失要先查颜色管线，
 不要先查几何**。

六、视觉评审（V3-5 最终）
====================================================================
 【达到的】硬边三分明暗（白外套 / 裤腿 / 拳套都可读出亮中暗）、
 粗墨线轮廓、明显体积感、大拳套与厚底靴、宽肩、凶眉与鼻影、
 双臂都可见（前后用明度区分）、红腰带/金扣/圆结、双环发髻。
 八帧 stance / jab / sweep / throw / hit_heavy 姿势可辨，
 enemy 配色与 12° 相机角生效。相比 V1 的「球 + 黑椭圆」和
 V2 的「扁平剪影」是两次质变。

 【已知遗留，不粉饰】
  1. 白外套为了不融白底被压成浅灰白，不是纯白；纯白背景仍偏廉价，
     真要「场景感」得加擂台背景与地面阴影（会牵动验收脚本的白底口径，
     本轮刻意没做）。
  2. 仍是程序化几何：无手指、布料褶皱、肌肉分块、表情变化。
  3. 正面正交没有纵深，jab 只表现为横向张臂（坐标桥红利换来的代价）。
  4. 腰侧环刃仍露出两个小暗弧；中国结是简化圆结。
  5. 【交付前最终看图追加】八帧对照图里 `sweep | impact f13` 左下有一块
     大的深灰 V 形箭头（极端膝折角下的腿带轮廓），其余 7 帧没有。
     **本轮未做对象级隔离，根因未证，不猜参数**；按第四节教训，下轮
     要修先 `diag_pose.py -- sweep 13 leg only` 隔离再动。11/11 判据
     不含「逐帧几何无自交」，所以这个缺陷不会触发任何红 —— 脚本判据
     覆盖不到的东西，必须靠看图补上。
  6. 手臂相对放大的拳套偏细（jab 帧尤其明显）；这是 V2 为避免三角翼
     把半宽砍到 5.5/4.2 game px 的代价，V3 只放大了拳套没同步加粗臂。

 【判据边界】11/11 只证明数据驱动 / 确定性 / 坐标正确 / 卡通渲染接线，
 **不证明好看、也不证明逐帧几何无自交**。像不像街霸、有没有断裂，
 是看图判的。

     脚本的白底口径）。成本中等。

     最接近 SF6，但会引入「渲染帧 vs 判定帧」同步问题，天级成本。
  C. 手绘 / SDXL 出精灵再切片：上限最高，但要重做 228 帧对齐，
     AI 多帧一致性是已知坑。
  D. 到此为止：作为设定/预览，运行时继续用 A 路线代码自绘外观层。成本 0。

 仍不建议现在渲 228 帧图集，除非先选定路线。
