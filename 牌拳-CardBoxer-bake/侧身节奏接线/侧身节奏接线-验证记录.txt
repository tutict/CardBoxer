二、做了什么
========================================================================
1) 开工前把 post-P0 游戏树 15 个源码文件备份到 orig/pre-side-rhythm/，
   写 备份指纹.json，BACKUP_OK files=15。
2) 新增 侧身节奏接线/battle_rhythm_spec.json —— 唯一数值真相来源。
   gen_rhythm_gd.py 从它生成 牌拳-CardBoxer/scripts/battle_rhythm.gd
   （3848 B，纯常量 + 纯函数，无节点无状态），GEN_RHYTHM_OK，
   逐字节可复现（R05）。
3) arena.gd 新增节奏层：
     const Rhythm = preload("res://scripts/battle_rhythm.gd")
     tk_rhythm_t / tk_rhythm_winner / tk_rhythm_hit
     _tick_rhythm() / _apply_rhythm_visuals() / _clear_rhythm_visuals()
     _draw_rhythm_fx(canvas)   ← 速度线、星芒火花、HIT! 标签
   _tick_taikou() 开头驱动；_resolve_taikou() 末尾只在非平局时启动节奏；
   hitstop 分支加 _maybe_capture()，否则命中停顿帧根本截不到。
4) fighter.gd 新增纯绘制层字段 visual_shift / visual_tilt，
   只在 _draw() 的 draw_set_transform 与 _draw_shadow() 生效，
   不碰 position / tick() / apply_hit() / _build_pose()。
5) 新增 tests/battle_rhythm_check.gd（10076 B，62/62 passed）。

  ① R19 首跑 19/20：初版写死「每个 P0 形态 count == 1」，

     双方各播一次 = 2 处真实调用，post-P0 基线也是 2。
     改为「期望计数从基线独立复算 + 全为真实代码行 + 非零」，

     「真实代码行恰好 1 处且 strip == _maybe_capture()」，
     R13 从裸 count 改为逐行排除注释，R19 复用同一 helper。
     重跑后 M20 CAUGHT，正常态仍 20/20。

========================================================================
七、边界 / 没做的事
========================================================================
* 这是 2D 自绘外观层上的节奏表现层，不是侧身 55° 立绘进游戏，
  更不是真 3D 蒙皮；角色几何仍是代码画的。
* 8 张截帧是注入态 GL 渲染，不是真人录屏；离线 GIF 未重渲。
* 离线 make_side_battle.py 一个字节没改（R09 用归档清单 sha256 证明），
  侧身战斗演示的 18/18 判据与 8/8 变异结论保持原样。
* battle_motion_spec.json 里标 new 的 10 项动作仍然一项没烘。
* 没渲 228 帧图集、没导 glTF、没进 Godot 3D、没验证贴地与自交。
* 20 条判据只钉可复算事实，不评造型、不评手感。
