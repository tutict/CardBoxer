二、路线：为什么是「图生 3D + Blender」而不是程序化几何
----------------------------------------------------------------
  程序化几何积木人已经被工程师否掉三次（「没有人样」「太丑」
  「为啥一定要火柴人风格」）。上一轮刚定稿的 2D 概念图是唯一已确认的
  造型依据，所以本轮走 **image-to-3D**：造型由图像决定，Blender 负责
  归一化、骨架、权重、保存 `.blend` 和同相机渲染 —— 这才是「建模」的
  实质增量，不是「导入看一眼」。

  本地工具边界（执行前已声明）：Blender 5.2.3 便携版 headless +
  本机多模态 3D 生成；产物全在 `对手怪Blender建模V1/`，不写进游戏目录；
  生成模型进引擎前仍需 Creative Review，本轮只到 `.blend` 与 PNG。

四、Blender 建模做了什么（`foe_blender_build.py`）
----------------------------------------------------------------
  1. 导入 GLB：1 mesh、64,024 顶点、79,998 三角、1 层 UV、3 张 4096² PBR。
     原始 bbox z=[0, 1.01451] m。
  2. 归一化到游戏坐标桥：scale **1.695408**，bbox z=[0.0, 1.72]、
     x=±0.60843、y=±0.36025。**与 `render_character.py` 逐行同口径**，
     所以能和玩家 V4b 直接并排。
  3. 用 `boxer_rig.BONES` 建 13 骨 Armature（hips…shin_b）。
  4. 刚性权重兜底：每顶点归到最近的骨骼段、权重 1.0，
     **64,024/64,024 = 100% 覆盖**。Bone Heat 已知 0 覆盖，这是可动兜底。
     分布本身暴露了不匹配：`chest` 只分到 666 顶点、`head` 410，
     而 `thigh_f/b` 各约 1 万 —— 模型宽 1.2168 m，玩家骨架 REST 只有
     ±0.44 m，大量躯干/头部顶点被外侧肢骨吸走。
  5. 灯光/正交相机与 V4b 完全相同；渲 front / angle25 / angle55 /
     back35 四视角 768² + upper 1024²，透明底、保留 PBR、不加 toon / 描边。
  6. 保存 `对手怪V1.blend`（模型 + 骨架 + 权重 + 相机灯光），
     打开即可直接渲。


五、剪影实测（`measure_silhouette.py`，同相机同身高）
----------------------------------------------------------------
    判据（先验阈值，不是事后凑）        实测          结果
    明度比 foe/player <= 0.75          0.5746        PASS
    肩部跨度比 >= 1.15                 1.1561        PASS（勉强）
    宽高比 >= 1.15                     0.9713        **FAIL**

  玩家 V4b bbox (174,96,594,672) = 420×576，aspect 0.7292、lum 0.5667；
  对手怪 bbox (180,96,588,672) = 408×576，aspect 0.7083、lum 0.3256。
  **对手怪整体外轮廓反而比玩家窄 12px** —— 玩家有明黄披肩和长飘带撑宽，
  图生 3D 把「宽肩厚躯」压成了更紧凑的敦实比例。所以「一眼可分」
  目前靠明度和肩部，不靠整体体量。这是造型要不要再迭代的硬依据。


六、变形探针（`probe_deform.py`）
----------------------------------------------------------------
  打开已保存的 `.blend`，把 `upperarm_f` 绕局部 Z 转 35°，
  用 evaluated mesh 逐顶点比对：
    moved = 10,780/64,024 (0.16837)
    max_displacement = **0.47922 m**，mean = 0.04068 m
  `foe-deform-upperarm35.png` 看图确认：右臂被整片带走、拉成横向
  破布状并与肩脱开，其余躯干与腿不动。
  **结论：链路可动，不证明变形可用。** 想真正吃 `baked2.json` 的
  228 帧，必须先修拓扑（2,809 个开放壳）或换带骨架的资产。


七、判据订正两处（都是口径 bug，不是产物坏）
----------------------------------------------------------------
  * `blend_file_is_real_editable_asset` 初版按老格式魔数 `b"BLENDER"` 判，
    实测头 4 字节是 `28 B5 2F FD` —— **Blender 5.2.3 默认把 .blend 存成
    zstd 压缩**。改成「zstd 魔数 + `probe_deform.py` 真的 open_mainfile
    打开过它并驱动渲图」双证据，比猜魔数更承重。
  * `deform_probe_shows_motion_and_caveat` 初版钉「不证明变形可用」子串，
    而字段原文写的是「链路可动 ≠ 变形可用」，用 `≠` 表达了同义却匹配不上。
    改产物措辞为显式「链路可动，不证明变形可用」并重跑，让判据真能钉住
    「不隐藏不确定性」，而不是把判据放宽。

  订正后 14/14；这两条都先实测再改，没有直接放行。

九、看图结论（人的判断，不是脚本结论）
----------------------------------------------------------------
  正面：单角色完整、头到靴都在框内，无悬浮部件；宽肩厚躯、兜帽 +
  圆形呼吸面罩、铆接胸甲与斜跨带、超大护臂、工具腰带与垂牌、
  破布下摆、橙黄警示斜纹、厚底靴全部可读。
  55°：有真实侧面体积，背后破布披风可见，但那片披风像一块半透明
  灰板、边缘生硬（开放薄壳观感）。
  对照板：初版卡片底 `(42,46,56)` 太暗，深色对手怪轮廓发糊；
  两列**统一**提亮到 `(70,74,86)` 后清楚，保持同底公平性。
  这是本轮唯一靠看图抓出的展示缺陷，14 条判据一条都没评排版。

  **如实偏差**：概念图是**单肩**青色结晶，图生 3D 生成成**双肩对称**；
  手从「缠手带」变成机械爪；头身比偏大、整体比概念图更敦实；
  在同相机同灯光下 PBR 明显偏暗（实测明度 0.3256 vs 玩家 0.5667，
  这本是深浅设计目标，但也让细节在深底上不好读）。
