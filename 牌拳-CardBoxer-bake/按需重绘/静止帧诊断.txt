========================================================================
一、结论（先看这段）
========================================================================
「静止帧还在每帧重画」不是一处，而是 4 个 CanvasItem 各自无条件
queue_redraw()。其中 3 处可以安全地按需重绘，1 处必须保持原样：

  arena.gd 自身  + fx_layer.gd   → 可停刷（绘制输入完全可枚举）
  hud.gd                        → 可停刷（但脉冲动画要特殊处理）
  fighter.gd ×2                 → 不停刷：呼吸/步态逐帧连续，签名每帧都变

判定手段不用「手工登记脏标记」（漏一个 setter 就是静默旧画面），改用
**绘制输入快照**：把每个 _draw() 会读的全部状态串成一个键，与上一帧比对，
键变才 queue_redraw()。外部注入式截帧脚本直接改 arena 字段时，下一帧
自然被检测出来，不需要它们配合调 API。

安全边界先写死：
  * 第一帧必须重画（_force_redraw 初值 true，且 last_key 用空串哨兵）。
  * 震屏期间必须逐帧重画：_shake_offset() 用 randf_range，缓存的绘制命令
    会与新的 world.position 不一致。
  * HUD 的 _time 只在「确实有低血量/满怒火脉冲在跑」时才进键；否则
    无条件进键会把每个真正静止的帧误判成脏，优化等于零。
  * _maybe_capture() 一律保留在 hitstop / 主分支，且不受停刷影响：
    RenderingServer.frame_post_draw 每渲染帧仍会触发，viewport 合成的是
    上一次缓存的绘制命令，像素不变。

三、静止期仍在变化的状态（决定「键」里必须放什么）
========================================================================
A. arena 自身 _draw()
     _flash（渐隐）、player.position.x / enemy.position.x（脚下反光）、
     _shake_offset()（_shake>0.05 时 randf_range 随机）、world.position。
   paint_fx() / paint_projectiles() 经 fx_layer 回调读：
     effects、projectiles、tk_rhythm_t、tk_rhythm_winner、tk_rhythm_hit、
     输家的 position.x 与 visual_shift、双方 visual_shift。
   注：上一轮已删的程序化夜空/楼群/闪烁灯窗不在本表内。

B. hud.gd
     _time：3 处脉冲源 —— _draw_bar_v2 的 r<0.3 填色、r<0.3 红框、
            _draw_rage_bar 的满槽边框；条件不成立时 _time 不影响任何像素。
     _hp_shown：move_toward 追 hp_ratio，约 3 秒内收敛，之后恒定。
     arena 字段（逐项在 hud.gd 的 _draw* 里出现过）：battle_mode、
       tk_player_rage / tk_enemy_rage / tk_turn / TK_MAX_TURNS、
       round_time_left / round_wins / round_phase、hand / cooldowns /
       cooldown_total / selected_index、tk_phase / tk_marks /
       tk_player_reveal / tk_enemy_reveal / tk_player_result /
       tk_enemy_result / tk_winner / tk_player_ex / tk_enemy_ex /
       tk_player_ex_boosted / tk_enemy_ex_boosted / tk_motion_id /
       tk_motion_label / tk_react_id、banner_time / banner_text /
       banner_sub / banner_color、combo_shown / combo_count；
       player/enemy 的 hp / meter / display_name。
     cooldowns 在 realtime 模式每帧递减；taikou 模式 _tick_taikou()
       不碰 cooldowns —— 这正是回合制里 HUD 能整段静止的原因。

C. fighter.gd（不门控，但要说明为什么）
     _breath 每帧 +delta，被 _draw() 的辉光、guard 弧、_build_pose()
     的 breathe 偏移读；_walk_time / _walk_blend / state_time /
     _phase_time / _flash / _stun_tilt / _ko_time / visual_shift /
     visual_tilt 也全在绘制链上。只要角色在场，签名每帧都不同。
     => 接门控的收益是 0，成本是改 12 套动作自检依赖的 tick() 行为。

四、截帧链与节奏层的依赖
========================================================================
1) arena.gd::_maybe_capture()：在 hitstop 分支（363-365）与主分支（401）
   各调一次，await RenderingServer.frame_post_draw 后存 PNG。paused 分支
   **没有**调用。停刷不影响它：viewport 每帧仍合成，缓存命令仍在。
2) 侧身节奏接线/capture_rhythm.py：先注入亮牌/结算状态，再手动推进
   _tick_rhythm(0.08)，最后 _global_hitstop = 10.0 把节奏时钟定格，靠
   hitstop 分支逐帧重画 + _maybe_capture() 抓「HIT!」那一帧。
   => hitstop 分支必须保留；且 arena 键要含 tk_rhythm_t / visual_shift。
3) 动作接线P0 / capture_p0.py、怒火槽截帧、引擎优化/capture_regression.py
   全部复用同一注入链；键含 hand / tk_* / banner_* 才能不出现旧 HUD。
4) tests/motion_strip.gd / walk_strip.gd 显式调 f.queue_redraw() 后
   await frame_post_draw；fighter.gd 不改，这两条不动。
5) tests/perf_probe.gd：arena.paused = true + 隐藏全部动态子节点，依赖
   paused 分支的 queue_redraw() 得到确定性纯背景。停刷后同样像素，
   但绘制命令只在第一帧提交 —— 这正是 CPU 收益的测量窗口。
6) 节奏层 _apply_rhythm_visuals() 自己调 winner/loser.queue_redraw()，
   属于条件触发的显式刷新，保留；不依赖 _process 的无条件刷。

========================================================================
五、可停刷条件与成本账
========================================================================
停刷条件（四者同时成立才跳过某一层的 queue_redraw）：
  ① redraw_gate_enabled == true（验收用可关，默认开）；
  ② 不是第一帧、也没有 force_redraw()；
  ③ 该层的绘制输入快照与上一帧逐字相同；
  ④ 该层没有「非确定绘制源」：arena 的 _shake<=0.05；HUD 的脉冲条件
     成立时把 _time 放进键（等价于强制逐帧重画）。

成本账：
  * 收益侧：冻结态（paused / 定格 / 无脉冲的 taikou select 段）
    arena + fx_layer + hud 三层每帧各少一次完整 _draw()。hud 那次最贵
    —— 5 张卡牌、多段 draw_string、6 条色带、刻度线全部重发。
  * 成本侧：每帧多算 2 个快照字符串（约 15 + 40 个标量/数组），
    远比一次完整 _draw() 便宜；不新增节点、不改判定、不改动作表。
  * 风险侧：漏列一个绘制输入 = 那一层画面停更。防御是
    tests/redraw_gate_check.gd 的源码级「hud 里出现的每个 arena.<field>
    都必须在快照表里」+ 注入态 4 路逐像素 A/B + 变异验证。
  * 不承诺：live 战斗动作期间不省 CPU（角色呼吸本来就每帧变），
    process_ms 是窗口采样不是 CPU 微基准，与 引擎优化/ 同口径。
