一、要解决的问题（上一轮 3D攻击GIF/ 的证伪结论）
------------------------------------------------------------------------
真 3D 网格一动就撕成扇形薄片，是三个原因叠在一起，不是单一权重问题：

  1. 模型是 A-pose，骨架 rest 却是格斗站架（boxer_rig.BONES）；
  2. 权重按「最近骨段刚性 1.0」分配，2,809 个开放薄壳被整片带走；
  3. 驱动方式是绝对骨位 pb.matrix = 摆到 baked2.json 的关节坐标，
     等于把 A-pose 模型硬扭成站架 —— 连站架帧本身就已经折叠。

已有前置证据（拓扑修复探针V1/）：原高模直接 ARMATURE_AUTO 报
「Bone Heat failed」，覆盖 0/64,024；Voxel 0.020 代理壳可让自动权重
覆盖 19,998/20,006；Voxel Proxy + Data Transfer 可把权重回传高模，
64,006/64,024 覆盖且 UV / 3 张 4096² PBR 全保留。
本轮把这条探针正式接成可驱动的动画链，并做 A/B 定量验证。

二、修复链（c_build.py，五个环节缺一不可）
------------------------------------------------------------------------
  1. A-pose rest 13 骨：用 3D攻击GIF/apose_joints.json 的正面标定换算成
     Blender 3D，重建与模型形状对齐的骨架（head_top_z=1.7105 / hip_z=0.8420）。
     骨名：chest / forearm_b / forearm_f / head / hips / neck / shin_b /
     shin_f / spine / thigh_b / thigh_f / upperarm_b / upperarm_f。
  2. Voxel 0.020 连续壳：2,809 壳 -> 3 壳；代理 20,204 顶点 / 20,198 面；
     ARMATURE_AUTO 覆盖 20,196/20,204 = 99.96%。
  3. Data Transfer（VGROUP_WEIGHTS / POLYINTERP_NEAREST）把平滑权重回传
     64,024 顶点高模；UV 1 层 / 材质 1 / 3 张 4096² PBR 逐项保留。
  4. 相对 rest 的增量驱动：每帧只算 baked2.json 相对站架的骨角差
     （wrap 到 ±pi），绕各自 rest head 做层级 RotY，绝不绝对摆位。
     站架帧 delta=0，复合变换恒等。
  5. 显式 retarget 层：复用 3D攻击GIF/puppet_mapping.json 的同一公式与参数，
     只去掉 2D 专用的「前臂放大」透视。不复用会重演第一版失败：
     hips/spine/chest 各拿到同一个 19.96°/27.18° 并在层级累积三次，
     整个人斜转 60°/81°、cross 横躺；cross 后手 -147.62°、wave 后臂
     +162.08° 是侧视动作表语义与正视 A-pose 模型错配。

四、增益 sweep（本轮新增，回答「动作幅度为什么还是小」）
------------------------------------------------------------------------
看图发现：撕裂修好了，但三档动作幅度明显小于上一轮 puppet 版。
根因假设是 retarget 参数原本给 2D 纸片人调，3D 网格的平滑权重会摊薄
同样的骨角。为把「能不能放大」变成可复算数字，跑 7 档 × 3 卡 = 21 帧：

  all（arm_gain / torso_gain / torso_cap / leg_cap 一起放大）
    gain   jab 幅度/撕裂        cross 幅度/撕裂       wave 幅度/撕裂
    x1.0   21.39° / 0.01806 m   28.00° / 0.04000 m   13.56° / 0.01950 m
    x1.5   32.09° / 0.02708 m   42.00° / 0.05718 m   20.35° / 0.02868 m
    x2.0   42.79° / 0.03573 m   56.00° / 0.07179 m   27.13° / 0.03758 m
    x3.0   64.18° / 0.05121 m   84.00° / 0.09365 m   40.70° / 0.05284 m

  arm_only（只放大 arm_gain_deg，torso/leg 保持 x1.0）
    x1.5   32.09° / 0.02808 m   42.00° / 0.05411 m   20.35° / 0.02749 m
    x2.0   42.79° / 0.03793 m   56.00° / 0.06625 m   27.13° / 0.03519 m
    x3.0   64.18° / 0.05482 m   84.00° / 0.08422 m   40.70° / 0.04972 m

  最坏 p999 = 0.09365 m，只有刚性基线 0.28048 m 的 33.4%：
  连续壳 + 平滑权重在全部 7 档都成立，撕裂不再是瓶颈。

  看图结论（增益-姿态对照板.png，cross#12 同帧）：
    x1.0  all      直立、人形完整，幅度小
    x1.5  all      直立、人形完整，伸臂明显更可读  <- 推荐
    x2.0  all      略侧倾，剪影仍完整              <- 勉强可用
    x3.0  all      躯干斜转约 45°、手臂冲出画面    <- 不可用
    x3.0  arm_only 躯干保持直立，但手臂抬出画面上方 <- 不可用
  毁姿态的是 torso_gain / torso_cap 被一起放大，不是拓扑也不是权重。
  可用区间 x1.0 .. x1.5（x2.0 勉强）。要放大只调 arm_gain_deg。

六、负结果与判据订正（按发生顺序）
------------------------------------------------------------------------
  1. 第一次 c_build.py 删旧骨架后继续用对象引用，报
     StructRNA of type Object has been removed；改为先存 old_rig_name 字符串。
  2. 站架恒等初版用精确相等判红（vertices_identical=False），但
     delta0=0 / root0=0，实测是 pb.matrix 往返的 6.43e-07 m 浮点漂移。
     改成 1e-05 m 工程容差，并把 max/mean 都写进报告，不接受「差不多」。
  3. 第三轮看图出现整个人斜转 / 横躺 / 细长尖片，根因是 retarget 缺失
     （上面 II.5）。复用 puppet_mapping.json 后消失。
  4. 像素幅度指标两版全部失败，已退役，只留在 gain_sweep.json 里：
       V1 逐像素 RGB/alpha 差异 / 前景并集 -> 0.71..0.80，与增益无关；
       V2 alpha 轮廓 XOR / 前景并集 -> 0.35..0.57，jab 随增益反而下降。
     两者都被 EEVEE TAA / 半透明边缘抖动与 root 平移污染。最终改用
     确定性几何量：max_delta_deg 作幅度、edge tear p999 作撕裂。
     这与 V3 建模时「颜色档数受 TAA 污染、不作判据」是同一个教训。
  5. M5 变异把 "DATA_TRANSFER" 改成 "DATA_TRANSFER_X" 后 C01 仍 PASS：
     C01 用宽松子串匹配，被包含原子串的无效类型名骗过。已把该 needle
     收紧为带引号的整串字面量 '"DATA_TRANSFER"'，复跑 7/7 CAUGHT。
  6. 两张新图各修过排版：对照板栏标题与副标题重叠（HEAD 76 -> 112）；
     权衡图数值标签被橙色数据点盖住（橙点先画、标签铺同色底板），
     x 轴标签与说明文字挤在一起（删面板底部说明），顶部写了
     「虚线=刚性基线」却没画虚线（改成指向下方数字）。
  7. make_filelist.py 打印 129、清单头写 130，自相矛盾；改为 build()
     直接返回行数并断言头部计数等于实际文件数，复跑 130/130 一致。
  8. GIF 编码会合并像素相同的连续帧（jab 14 -> 12、cross 22 -> 19、
     wave 36 -> 33），判据不钉「帧数守恒」，改钉
     「总播放时长守恒 + 编码帧数范围 + stats 双算」。
