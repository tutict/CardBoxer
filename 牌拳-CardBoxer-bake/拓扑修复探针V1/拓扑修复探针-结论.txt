《牌拳》人物建模：要不要上 ZBrush —— 可行性探针结论
================================================================
日期：2026-11-08
问题：工程师「需要 zbush 进行人物建模优化吗？」
结论：**不需要 ZBrush。** 买了也解决不了当前卡点。


一、先给结论
----------------------------------------------------------------
  当前瓶颈不是「雕得不够细」，是「AI 生成模型是 2,809 个开放薄壳、
  自动绑骨 0 覆盖、一动就散」。ZBrush 对症的只有一件事：ZRemesher
  把碎壳重建成连续网格。而这件事 Blender 5.2.3（本机已有、免费）
  2.64 秒就做完了，自动绑骨从 0% 拉到 99.96%~100%。

  更关键的是：剩下的没解决的问题（变形质量、A-pose 对格斗站架、
  228 帧动作链路）**ZBrush 根本不做**。它 2026.2.1 的动画能力是 None，
  一个 ZBrush 雕刻件仍必须离开 ZBrush 才能绑骨 / 动画 / 进引擎。
  所以这钱花在错误的环节上。


二、实测数字（全部本机 Blender 5.2.3，两次共 5.62 秒）
----------------------------------------------------------------
  基线  原始网格 64,024 顶点 / 79,998 面 / 2,809 连通壳 / 1 层 UV
        / 3 张 4096² PBR
        ARMATURE_AUTO -> Bone Heat failed，0/64,024 = 0.0%

  档 1  voxel_size 0.020 m
        体素重建后 20,204 顶点 / 20,198 面 / **3 个壳**
        自动权重 19,998/20,006 = **99.96%**

  档 2  voxel_size 0.035 m
        体素重建后 6,446 顶点 / 6,452 面 / **2 个壳**
        自动权重 6,446/6,446 = **100%**

  闭环  Voxel Proxy + Data Transfer 把平滑权重传回**原始高模**：
        64,006/64,024 = **99.97%** 覆盖；
        UV 1 层、材质 1 个、3 张 4096² PBR **逐项与原件一致**（贴图保住了）。
        渲静止正面图 `transfer-rest-front.png` 可见完整 PBR 人形。

  变形  upperarm_f 转 35°，同一 .blend / 同相机 / 同角度 A/B 对照：
        A 刚性权重(11-08 基线)  10,780 顶点动，max 0.47922 m，mean 0.04068
        B 代理壳平滑权重        22,252 顶点动，max 0.39142 m，mean 0.05677
        B 最大位移降 18.3%、影响范围翻倍（权重更连续）。

  壳数另有进程外独立 union-find 复核（读导出的 faces_*.json），
  不复用 Blender 脚本里的实现，两套数字逐项一致。


三、必须如实说的负结果：这没把变形救回来
----------------------------------------------------------------
  **A/B 两版在 35° 驱动下，画面右臂都不可见**（静止图双臂完整）。
  `transfer-compare-rigid.png` 与 `transfer-compare-transfer.png`
  右臂都只剩肩部一小块，平滑权重并没有消除这个现象。

  所以：99.97% 覆盖率 + 贴图保住 + 最大位移下降，
  **只证明「链路可动、资产没丢」，不证明变形可用**。
  而且这个现象未必全是撕裂 —— 驱动轴是 pose-bone local Z，
  有可能把整条手臂转到躯干后方被遮挡，需单独做驱动轴诊断才能定性。
  本探针不下定论，也不把覆盖率包装成通过。

  代理壳本身也不能当资产：`proxy-front.png` 里人形轮廓可辨，
  但表面被体素化溶蚀，面罩 / 胸甲 / 管线细节全糊、中间有浅色穿透区。
  这正是「只用代理壳算权重、最终仍渲原高模」的原因。

  还有一处口径要订正：0.020 档 DECIMATE 的 ratio 是 20000/20198≈0.990，
  面数从 20,198 变 20,476（几乎没降、反而因三角化略增）。
  **自动权重成功是体素重建本身的功劳，降面这一步在本例近似 no-op**，
  不能说成「降面到 2 万面才绑上」。0.035 档压根没触发降面。


四、成本账（2026-11-08 查证）
----------------------------------------------------------------
  ZBrush 2026.2.1（Maxon）：
    * 已停售永久许可，纯订阅；$49/月 或 $399/年（2026-08 核实）；
      另一价源于 2026-10-01 核实为 $35.90/月（年付，合计 $430.80）
      / $54/月（月付）；Maxon One 捆绑约 $1,265/年。
    * iPad 有免费版，但只有 28 支笔刷 / 2000 万面上限 / ZRemesher 受限，
      且是 iPad 端，不能进本机 headless 管线。
    * **本机未安装**（Program Files 下无 Maxon / Pixologic 目录）。
    * 隐性成本：安装授权、GoZ 往返、界面与操作学习、ZRemesher 后
      UV 重建 + 3 张 PBR 贴图重烘，仍是天级投入。

  Blender 5.2.3 LTS（本机 D:\Tools，已在用）：
    * 0 元、GPL、无需新装；两套探针共 5.62 秒；
    * 与现有 `boxer_rig.BONES` / `baked2.json` 坐标桥同一进程，
      不引入格式转换。

  ZBrush 真正值得买的条件（目前一条都不成立）：
    1. 要手工重塑造型 —— 比如把对手怪宽高比 0.9713 推过 1.15，
       靠雕刻加宽肩胸而不是再抽一次 AI 模型；
    2. 要千万级高模细节（皮肤、布纹）供近景；
    3. 要规整四边面拓扑承载近景关节弯曲。
  但《牌拳》C 路线进引擎的是 **2D 精灵 PNG**，不是 mesh，
  四边面拓扑质量对「渲图集」这件事没有收益 —— 这是最根本的不匹配。
