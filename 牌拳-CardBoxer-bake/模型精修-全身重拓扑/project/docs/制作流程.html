牌拳CARD BOXER

拿这套流水线做一款仿拳皇的横版格斗：角色不出招式指令，而是打牌——每张牌是一个动作， 牌序接上了就是连招，三张特定的牌加满气就是大招。全程不开大模型，只用它自己的确定性路径跑， 然后把每个阶段真实吐出来的东西记在这一页里。

01 / 一句话这条流水线强在哪，弱在哪

它把「一段中文点子」变成一套真能读的策划产物：玩法规格、GDD、引擎工程计划、QA 清单、 资产计划、创作评审、任务拆解。它甚至自己找到了本机的 Godot 4.6.3 可执行文件，跑完了 headless import。 但它最后交付的可玩东西是一个固定的 3D 第三人称灰盒，跟卡牌格斗没有半点关系——所以游戏本体是手写的， 设计输入取自它产出的那份 spec。

这不是「流水线坏了」。它在自己声明的范围内是准确的：preflight 会警告 「声明了 9 项资产需求但未启用 Blender，将退化为纯灰盒」，validate 逐个校验脚本， import 真起一次引擎。真正的问题在表达力：规格模板里没有「手牌」「连招」「2D 横版」这些词， 再聪明的执行也只能落到它认识的形状上。

03 / 卡点为什么最后是手写的

这四条是拿真实返回对照需求得出的，不是猜的。

卡点实际是什么后果
标题与语义丢失 标题是 Createa10-MinuteGo——把 prompt 前几个词串起来再按 PascalCase 拼接；中文创意在确定性路径里没有被解析。 产物读起来像占位符
没有卡牌词汇 核心动词固定为 position / attack / evade / recover；spec 里没有 hand、deck、combo、super 这些字段。 卡牌玩法无处安放
产物是 3D 灰盒 生成的是 CharacterBody3D 第三人称控制器与追逃敌人；轴表里八种机制（含 combat）都是 3D 模板。 做不出 2D 横版
验收过不去 playtest 判 no_win_path：它自己生成的灰盒，bot 打不赢。 成品不可交付
所以分工是这样定的：流水线负责策划段（规格、GDD、工程计划、QA 清单）， 其中四条失败压力被直接搬进卡牌设计——「贪伤害要有可见代价」变成气耗与后摇， 「位置本身是伤害来源」变成突进与后撤，「可读的前摇才有惩罚窗口」变成 AI 读招。 游戏本体、卡牌表、连招表、AI 与画面全部手写。

04 / 本体牌拳怎么玩

三局两胜，每回合 60 秒。手上有 5 张牌，每张牌就是一个动作；出牌即出招，没有搓招指令。 牌序命中连招表就加伤，三张特定牌加 3 点气触发大招。

命中瞬间：停帧 0.07 秒、震屏、放射火花、描边伤害数字，受击方后仰。
贴身对拼。卡面标着气耗与一句用法；气不够的牌整张压暗。

开发过程中被这条自动对战链抓出来、并且已经修掉的真问题（都不是表现问题）：

问题症状根因
位移牌不位移打「突进」只有冲刺姿势，人没动牌的数据写了，_on_active_start 里没实现
整手没有攻击牌 → 死锁双方贴脸站着十几秒，血量与气纹丝不动抽牌只保证开局一张起手牌；气只能靠命中获得
连招时间窗算错隔几十秒的两张牌也会被判成连段用 state_time 计时，而出牌会把它归零
气功波永远打不中波从对手胸口穿过去多写了一条 y 轴判定，横版格斗里没有纵轴
伤害数字看不见命中有效果没数字特效画在父节点，被角色盖住；且浅色躯干吃掉了对比度

操作

1–5 打出对应手牌  ·  A/D 或 ←/→ 移动  ·  R 重开一场  ·  空格 暂停

开发时另有两个开关（只认环境变量，不介入玩法）： CARD_BOXER_BOT=1 让玩家侧也交给 AI 自动打； CARD_BOXER_CAPTURE=<目录> 配 CARD_BOXER_CAPTURE_AT=秒,秒 在指定时刻截图， 再加 CARD_BOXER_CAPTURE_HIT=1 会在第一次真实命中时抓一张。
