────────────────────────────────────────
一、结论先行
────────────────────────────────────────
1. 「原来的火柴人」不是回归，是设计：运行游戏.bat 不带 CARD_BOXER_3D，
   arena.gd:221 的 use_3d = OS.get_environment("CARD_BOXER_3D") != "" 为 false，
   两个 Fighter 的 draw_3d_override 都保持 false，画的是 A 路线的 2D 代码自绘外观层。
   带 CARD_BOXER_3D=1 启动，两套 3D 表现层才会挂上并被读回（本次实测两侧 override 全 true）。

2. 「乱码」在 Godot 4.5 图形界面里没有复现。默认 / 开 3D 两种启动方式的
   1280x720 真实截帧里，中文 HUD、回合作战横幅、五张卡牌说明全部正常渲染。
   盘上逐项排除：0 条脚本错误、79 个文本文件全部严格 UTF-8、HUD 用 SystemFont
   且点名 Microsoft YaHei、命中标签 "HIT!" 是纯 ASCII、B round2 的 GLB 在引擎内
   资产读回 ok=true（贴图/顶点都正常，不是加载失败）。

3. 唯一能在盘上定位到的「乱码」来源不在游戏画面里，而在控制台：
   arena.gd:949 的 [TAIKOU] 回合日志含「你 / 青岚」等中文。若用 console 版 Godot
   从默认 GBK 代码页的 cmd 启动，UTF-8 中文会被按 GBK 解码成一串乱码。
   本轮跑 taikou_flow_check.gd 得 51/51，但该自检不触发 _resolve_taikou() 的 print，
   所以这一条是「源码级可核查的假设」，不是实证到的用户现场。如实标注。

4. 已止损：工程里装着我未验收的 B round2 GLB，先撤回到已知好的 I 基线。
   新增 运行游戏-3D.bat 让 3D 一步可见；原 运行游戏.bat 一个字节没改。

5. 仍未解决：用户看到的「乱码」具体在哪一层。需要一张现场截图或说明启动方式
   （双击 bat / 编辑器 F5 / console 版 / 4.6 打开），我按图定位，不猜。
