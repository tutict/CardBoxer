二、剧本（battle_script.json，可复算）
------------------------------------------------------------------------
牌型等级 triple=3 / sequence=2 / scatter=1，同牌型按 rank_sum 比大小
（**演示简化**，不等同 taikou_rules.gd 的完整太阁 IV 规则，已在 JSON 里
明说 `_not_claimed`）。动作与伤害不手写，从
combat-motion-design/battle_motion_spec.json 的 card_type_binding / damage_tiers 取。

  回  玩家牌     牌型     对手牌    牌型     赢家   动作   伤害
  1   [2,5,8]   散牌     [1,4,7]  散牌     玩家   刺拳    5
  2   [4,5,6]   三连     [8,8,8]  三同     对手   气功波 14
  3   [9,9,9]   三同     [1,2,3]  三连     玩家   气功波 14

  血量/怒气轨迹（受击一次 +34 怒）：
    起始 100:100 / 0:0 → 100:95 / 0:34 → 86:95 / 34:34 → 86:81 / 34:68
  结算：三回结束，剩余兵力 86 > 81，玩家本局胜。

三、时间线（离线合成，12.5fps / 80ms 一帧）
------------------------------------------------------------------------
  每回 42 帧 = 3.36s，三回 126 帧 + 结算 14 帧 = **140 帧 / 11.2s**。

  段      帧      内容
  idle    0-5     站架、回合提示「第 N 回 / 3」、牌背
  reveal  6-17    同时亮牌、牌型横幅「散牌 VS 散牌」
  judge   18-20   判定定格 +「▶ 玩家胜出 / 对手胜出」
  attack  21-34   赢家按 baked2.json 逐帧出招并前压 120px；
                  输家击退 34px + 后仰 7° + 闪白 + 抖动；
                  冲击环、速度线、命中闪白、伤害数字上飘
  settle  35-41   血条插值扣减、怒气槽增长、双方回站架
  outro   14 帧   居中结算面板「玩家 V4b 胜 · 剩余兵力 86 : 81」

  攻击帧按源卡长度（jab 14 / cross 22 / wave 36）在 14 帧攻击窗内采样，
  时间曲线仍逐帧来自真实动作表，不是手摆关键帧。

四、看图迭代（按发生顺序，负结果全保留）
------------------------------------------------------------------------
  1. 首版两个角色各站一边、只抬手，没有「打到人」的感觉；横幅飘在背景上
     几乎看不见。改：站位从 218/662 收到 250/630，角色放大到 270/290px，
     赢家前压 120px、输家击退+后仰+闪白，横幅加深色底板。
  2. 速度线首版是 70~116px 纯白长横线，横穿人物像 UI 分割线。
     收成 4 条 26~48px 淡短斜线，且只画在两人之间的空隙 x=404..478。
  3. 两版对照首版贴整帧，两套对手怪外观接近看不出差别，还把牌型横幅的
     尾巴裁进画面。改成右侧对手区域裁切 (430,88,880,376) 并排放大，
     y 收到 376 避开横幅底板、同时保住脚底。
  4. **GIF 时长首版 11360 vs 期望 11620ms**：GIF 延迟以 10ms 为单位，
     83ms 被量化成 80/90ms、合并帧累加时丢了 260ms。改用 80ms
     （12.5fps），并钉死「frame_ms 必须是 10 的整数倍」判据 B06。
  5. **M5 变异逃逸**：把 `optimize=False` 改成 `optimize=True` 后 B12
     仍 PASS，因为该字符串在**注释里也有一份**，宽松子串被注释骗过。
     接线判据改钉真实调用形态
     `duration=FRAME_MS, loop=0, optimize=False, disposal=1)`，
     复跑 8/8。这与 C 路线 M5（DATA_TRANSFER_X 含原子串）是同一类坑。

六、边界（不宣称做到了什么）
------------------------------------------------------------------------
  · 这是**离线合成演示**，不是游戏内实机录屏，也没把 P0 动作规格
    接进 arena.gd；游戏源码 0 改动。
  · 受击是离线表现层（击退 / 后仰 / 闪白 / 抖动 / 冲击环），
    **不是新烘动作帧**；spec 里 hit_crush 本就标 new 未烘，
    hit_light/hit_heavy 虽有 react 轨道但 puppet 只渲了 jab/cross/wave。
  · 玩家 V4b 依旧是静态 A-pose / 0 skins，用的是 2D 立绘 puppet；
    真3D版只有对手侧换了 C 网格。双方真 3D 对打目前做不到。
  · 牌型比较是演示简化（rank_sum），不是完整太阁 IV 规则。
  · 角色是正视生成模型，动作表来自侧视 2D 关节，正面视角下
    「朝对手出拳」靠前压和速度线暗示，透视与朝向并不严格正确。
  · 没验逐帧自交 / 脚底贴地 / 228 帧全量 / glTF / Godot。
  · 15 条判据一条都没评「好不好看」，看图结论单写在本记录第四节。
