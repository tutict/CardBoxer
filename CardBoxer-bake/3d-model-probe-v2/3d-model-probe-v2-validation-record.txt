一、结论（先说结果）
---------------------------------------------------------
**造型这一半成了，结构那一半一点没变。**

  | | V1（黑白熊猫 / 琉音方向） | V2（本轮 / 神乐服装语言） |
  |---|---|---|
  | 观感 | 白外套 + 黑大拳套 + 双环发髻，偏「配齐了零件」 | 白色中式长衫 + 红盘扣 + 下摆靛蓝云纹 + 深蓝长裤 + 黑短靴，轮廓修长、配色统一 |
  | 拳套 | 两个大黑球 | **没有**，只有深色袖套/护腕 + 裸手 |
  | 像人 | 尚可 | 明显更像正常人；五官、体态、衣褶层次都更完整 |
  | 骨架/动画 | 0 / 0 | **0 / 0（完全没变）** |
  | 自动绑骨 | 0/51,587 覆盖 | **0/51,690 覆盖（实测，同样失败）** |
  | 连通壳 | 861 | **1,045（更多）** |

一句话：**换造型能让模型好看，但换不出骨架。** 上一轮「程序化 3D 有动作没造型、
生成 3D 有造型没动作」的结构性矛盾，本轮只解决了造型那一侧，另一侧原封不动。


二、查证与设计取舍
---------------------------------------------------------
多源核对（百度百科 / 360百科 / 搜狗百科 / newton.com.tw / 维基镜像 /
gintama.fandom.com / all-worlds-alliance.fandom.com / shapes.inc）一致：
《银魂完结篇·永远的万事屋》(2013) 五年后神乐是**白色长旗袍 + 下摆蓝色云纹
（取自银时浴衣）+ 红色盘扣 + 及腰长发 + 黑靴 + 巨伞**，气质转冷。
一篇 cos 文写「白底无袖上衣 + 蓝护腰 + 黄腰带 + 黑长手套 + 橘红长发 + 紫伞」，
与 8 个来源冲突，判为混搭/另一时期，**不采纳**。

提取的是**服装结构与配色关系**，不是角色：白长衫、下摆云纹带、红盘扣、长发、
黑靴、冷感。舍弃橙红发/蓝瞳/紫伞/斗篷/高开叉露肤，按《牌拳》既有口径做
中性全覆盖战斗服（开衩只到膝 + 内搭长裤）。完整取舍表见 `design-spec.txt`。

手部替代：软布缠手带 + 深色护腕 —— 保住拳手身份，去掉巨大球体。

四、结构检查（inspect_model_v2.py）
---------------------------------------------------------
**这一轮的坑：URL 顺序会变。** V1 是 `01.zip / 02.png / 03.glb / 04.fbx`，
V2 是 `01.png / 02.zip / 03.glb / 04.fbx`。V1 的 `inspect_model.py` 按编号
硬编码，直接复制到 V2 会把 PNG 当 ZIP 读（静默错）。V2 检查器改成**按文件魔数**
分类 `glTF / \x89PNG / PK / Kaydara FBX Binary`，并把 union-find 连通壳统计并进来。
又一次「按形状，不按名字」。

  | 项 | V2 值 |
  |---|---:|
  | GLB version / 声明长度 / 文件字节 | 2 / 30,790,380 / 30,790,380（一致）|
  | scene / node / mesh / material / primitive | 1 / 1 / 1 / 1 / 1 |
  | 顶点 / 三角形 | 51,690 / 79,960 |
  | texture / image | 3 / 3（embedded，PBR）|
  | **skins / animations / cameras / rig-like nodes** | **0 / 0 / 0 / 0** |
  | **连通壳（union-find）** | **1,045**，top10 [2203,1983,1355,1217,1212,1125,1087,1035,1023,918] |
  | FBX token | LimbNode/Deformer/Skin/Skeleton/BindPose/Animation 全 0；Geometry 4 / Material 12 / Texture 27 |
  | ZIP | 6 项（4 张 PBR PNG + OBJ 5,204,814 B + MTL 245 B）|

`inspect_model.log` 尾行 `INSPECT_V2_OK`。


五、绑骨复核（Blender 5.2.3 LTS，probe_rigfit_v2.py，2.71s）
---------------------------------------------------------
不是为了「再试一次运气」，是为了证明「换了造型，结构结论是否仍成立」——
**结果是实测 0 覆盖，不是从 V1 推出来的**。

  | 项 | V2 值 |
  |---|---:|
  | 导入 mesh / 顶点 | 1（`node_0`）/ 51,690 |
  | 归一化 scale（到 1.72 m） | 1.556579 |
  | 归一化 bbox | x ±0.3987、y ±0.2010、z [0, 1.72] |
  | `ARMATURE_AUTO` | `Warning: Bone Heat Weighting: failed to find solution for one or more bones` |
  | 顶点组 / 覆盖 | **0 / 51,690 = 0.0** |

REST 关节到最近网格顶点距离（米）：hip 0.0324 / shoulder 0.0110 / head 0.0156 /
f_elbow 0.1111 / **f_hand 0.3382** / b_elbow 0.0304 / b_hand 0.0023 /
f_knee 0.0281 / f_foot 0.0380 / b_knee 0.0356 / b_foot 0.1085。
只有 `f_hand` 超出 0.12 m；z=1.56 处模型 x 范围 [-0.1484, 0.1016]，
而 REST 护脸手要 x=0.44 —— **A-pose vs 格斗站架的姿势差仍在**（比 V1 的
0.2723 m 更大，因为长衫下摆更宽、手臂更贴身）。

**判据卫生**：`probe_rigfit_v2.py` 是从 V1 复制的，里面仍硬编码
`artifact_03.glb`。V2 恰好也是 03 号所以没读错，但这是运气不是设计——
下次顺序再变就会静默用错文件。已在第九节列为待修项，不假装它稳。


六、看图结论（V1-V2-model-comparison.png，1174×620）
---------------------------------------------------------
**改对的地方**：白长衫的立领与斜襟红盘扣连成一条清楚的中线；下摆靛蓝云纹
是整套衣服唯一的大面积装饰，位置、比例都对；深蓝袖套/长裤把白衫衬出来；
没有拳套之后手臂线条连贯，头身比更修长；侧开衩有红边、内搭长裤，
没有出现露肤；全身无悬浮部件、无底座、无背景。整体比 V1「白外套 + 两个黑球」
更像一个真实的人。

**没做到的 / 偏差（不粉饰）**：
  1. **头发是高丸子头，不是及腰长发低束** —— prompt 写了 waist-length black
     hair half tied low，生成器收敛成了发髻。要精确控制发型得用图生 3D 或改图。
  2. 手指偏细长，裸手在 512² 预览里略显无力；缠手带没被生成出来，
     实际只有深色袖套到腕。
  3. 云纹被简化成「浪花/漩涡」而非传统如意云头，是风格化近似。
  4. 仍是 A-pose，不是格斗站架；不能当动作帧用。
  5. 造型是否「好看」由看图判，脚本一条都没在评这件事。


七、未验证项 / 没做的事
---------------------------------------------------------
* 没渲任何动画帧 / 228 帧图集 / 抠底打包 / 锚点；没做 alpha 检查。
* 没试封壳重拓扑后 bone heat 是否恢复；没验证 glTF 进 Godot、没重写 toon shader。
* 没做 IP 合规审查（只作服装语言参考，见 `design-spec.txt` 第三节）。
* 没改进程序化 3D B 路线（`boxer_3d.py` 一行未动）——按上一轮判断已退役为
  坐标桥/骨架的技术证据，不再往造型上投时间。
* 本轮是探针不是回归守卫，没写 test suite、没做变异验证；承重结论靠
  「不同实现/不同模型各跑一次」互证。
