一、结论（先看这段）
------------------------------------------------------------------------
  成立：做出了一局三回、双方真正侧身相对的离线战斗 GIF。相比上一轮
  正视立绘版，同一命中帧画面差异 65,857 px，改进主要在「两人面对面 +
  贴身水平前压 + 地面投影 + 命中火花与 3 帧停顿」。

  不成立 / 不能宣称：这仍是 2D 图像空间变形，不是真 3D 蒙皮动画；
  玩家 V4b 与对手怪都还是静态 A-pose 模型渲出来的立绘；动作幅度偏小；
  若干帧仍有小三角碎片；没有烘受击轨道；没有验逐帧自交与贴地。

  验收：verify_side.py 18/18 PASS / SIDE_BATTLE_VERIFIED

二、为什么改了三版站架、两版动作、三版合成
------------------------------------------------------------------------
  【站架探针 V1】13 个刚性分区各自仿射再 alpha 合成，偏移一大，
  长发 / 披风 / 白色长衫下摆被拉成悬浮片，对手怪头部被水平切成两半。
  负结果留在 frames/stance_probe_v1/。

  【站架探针 V2】猜是「离骨段太远的像素被硬分给手臂」，加
  build_masks_safe 把 far_px 之外的像素钉到 hips 恒等层。长发/披风
  保住了，但对手怪头部仍有一道白色楔形缺口、披风被挖空、玩家下摆
  有横缝。根因不是远像素，是**分区边界**：相邻块变换差几十度，
  MaxFilter 扩 1px 根本盖不住。负结果留在 frames/stance_probe_v2/。

  【站架探针 V3 = 定稿】改 mesh_warp.py：规则网格每个顶点按最近两段骨
  的位移混合求连续位移场，用 PIL Image.Transform.MESH 把格子映射成
  四边形。相邻格子共享顶点位移 → 边界严丝合缝，白色楔形消失。
  24px 网格 = 1,024 格，813/816 个顶点判为附属物归 hips。
  三档 S1/S2/S3 看图选 S2：护脸/收腰/前后脚最可读，S1 太接近 A-pose，
  S3 碎片变多。选组用 make_side_stance.py --select S2 钉进
  side_stance.json；站架帧与 S2 探针 PNG **逐字节一致**（S02 判据）。

  【动作帧 V1】局部相对角差虽消除了 hips/spine/chest 三重累积，但
  gain=1.0 / 手臂 cap 40 度，叠加站架 S2 后 cross f13 玩家上身折成
  两半、长发飞离，对手怪缩成一团。
  【动作帧 V2 = 定稿】gain 0.55、root_gain 0.6、躯干链 caps 5/4/3/5、
  手臂 18、腿 8。人形保持直立、四档手臂位置可读。动作表世界方向角差
  最大 179.099 度，经局部分解+限幅后局部最大 18 度。

  【合成 V1】横幅 y=390..410 正好压住脚底、地面线和投影；火花是大椭圆
  环，缩到战斗画布像靶心 UI。
  【合成 V2】横幅收进 HUD 中部空白（x=308..572, y=50..72）——这是唯一
  既不遮角色（角色头顶 y≈74）也不遮出牌区的位置；站位收到 240px；
  火花改白色核心+12 道星芒；前压 110 / 击退 40 / 后仰 9 度。
  【合成 V3 = 定稿】发现 HIT! 标签是死代码：停顿帧传的是 f=27，
  `f in HITSTOP` 永远 False。改成显式 stop= 参数；前压改三角脉冲
  `110 * max(0, 1 - |t-0.45|/0.30)`，只在命中瞬间贴近，出击前后拉开。

三、关键口径（判据钉的就是这些）
------------------------------------------------------------------------
  1. 侧视语义对齐：两张 55° 原图角色脸朝画面左，而 baked2.json 是
     角色朝 +x 的侧视动作表（f=前手在 +x、b=后手在 -x）。**先水平
     翻转源图**，f/b 才与动作表同向，因此不做正视版
     puppet_mapping.json 的重定向。合成时玩家不翻（朝右）、对手翻一次
     （朝左），两人真正相对。
  2. 局部相对角差：Δφ_i = wrap(Δθ_i - Δθ_parent)；根骨 hips 强制 0
     （附属物归 hips，只随 root 平移），躯干倾角只给 spine 一次。
     这是相对正面版「三段各拿 27.18 度累积三次」的修正。
  3. 站架偏移是**外观基线**，不是动作帧：它把 A-pose 掰成格斗预备式，
     每帧动作增量才逐帧来自动作表。side_stance.json 的 _not_claimed
     明说这一点。
  4. caps 只做逐帧限幅，不改写时间曲线、不重映射方向、不手工摆关键帧。
  5. GIF 延迟单位是 10ms：沿用 80ms / 12.5fps / optimize=False /
     disposal=1，总时长守恒 11,200ms。

六、边界（不宣称做到了什么）
------------------------------------------------------------------------
  · 离线合成演示，不是实机录屏；没把 P0 动作规格接进 arena.gd。
  · 受击是离线表现层（击退 / 后仰 / 闪白 / 抖动 / 火花），不是新烘
    动作帧；battle_motion_spec.json 里 hit_crush 本就标 new 未烘。
  · 55° 立绘是 3/4 侧视不是纯 90° 侧视，透视与游戏 2D 判定平面
    不严格等价；牌型比较是演示简化 rank_sum，不是完整太阁 IV 规则。
  · 动作幅度偏小（gain 0.55 的代价），三档之间的差别主要靠手臂位置
    与整体前压读出；对手怪暗色材质在暗背景上的动作可读性弱于玩家。
  · V3 仍残存小三角碎片（玩家腰侧、对手脚底尖片），缩到 310px 角色
    高度后约 7px，需在 768 原图放大才明显；不宣称「无碎片」。
  · 没渲 228 帧全量、没导 glTF / 进 Godot、没验逐帧自交与脚底贴地。
  · 18 条判据一条都没评「好不好看」，看图结论单写在第二节。
