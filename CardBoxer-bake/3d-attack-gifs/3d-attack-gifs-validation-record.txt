1. 结论（先说结果）
======================================================================

用户要看的是「新的 3D 建模人物」打拳的动图，不是上一轮误做的
「游戏内 2D 自绘外观层」。本轮纠正方向后，实测两条路线：

  * 真 3D 网格 + 13 骨刚性权重驱动：**证伪，不能交付当动画**。
    64,024/64,024 顶点全部移动，平均位移 0.26873 m、最大 0.88084 m，
    站架帧就已折叠，jab/wave 手臂炸成扇形薄片。
  * 3D 渲染立绘 + 图像空间骨骼重定向（puppet）：**可以动、人形完整**，
    玩家 V4b 与对手怪 V1 各出三档攻击 GIF。但动作幅度保守，读作
    「抬臂前冲」而不是真正出拳，是 C 路线的节奏预览，不是成品战斗动作。

因此本轮交付 3 套（9 条单档 GIF + 3 条连播 + 6 张对照/时间线板），
其中「证伪-网格」一套是**反例证据**，不是可用素材。

15 条承重判据 15/15 PASS / ATTACK_3D_VERIFIED；
6 组变异 6/6 CAUGHT、逐字节还原 6/6、clean re-run 15/15；
DID NOT RUN 分支自检 5/6 CAUGHT + did_not_run=1 / DID_NOT_RUN_SELFTEST_OK。
游戏源码 7 个文件与 `combat-motion-design/source-baseline.json` 逐字节一致，0 改动。

3. 三条路线与看图结果
======================================================================

| 路线 | 做法 | 结果 |
|---|---|---|
| A 真 3D 网格 | 打开 .blend，13 骨 `pb.matrix` 逐帧摆位（只旋转、不写 scale） | 碎片、折叠、手臂扇形撕裂 |

A 路线为什么撕：模型是 A-pose / 0 skins / 数千开放薄壳，
`foe_blender_build.py` 当初按「格斗站架骨段」给每顶点最近段刚性权重 1.0。
绝对骨位一摆，薄壳被整片带走；连站架帧都不是原模型。
这不是渲染参数问题，是「A-pose 模型 + 站架骨架 + 刚性权重」的结构矛盾。

B/C 路线为什么能看：C 路线进引擎的本来就是 2D 精灵 PNG，
所以在**图像空间**做骨骼变形，保留 3D 立绘的全部 PBR 外观细节，
动作时间曲线仍逐帧来自 baked2.json。

4. 三次看图迭代与根因订正（都是实测，不是推测）
======================================================================

v1：把 `baked2.json` 的逐骨方向角差直接当本地旋转增量套到正面立绘。
  * `atan2` 跨 ±π 分支未归一化，jab 第 7 帧算出 310.194°「增量」，
    wave 第 18 帧 199.019° → 整条手臂绕肩转大半圈。
  * 修：加 `wrap_pi()`，jab 降为 63.867°（原始）/ wave 162.075°（原始）。
  * 判据 `angle_wrap_wired_and_bounded` 钉住源码接线 + 映射后最大角 <= 40°。

v1 看图：整个人斜转 60°、腿飞出去。`diag_delta.py` 逐骨打印定位：
  * `hips / spine / chest` 三段拿到**完全相同**的 19.96°（jab）/ 27.18°（cross），
    层级左乘被累积三次 → 整个人绕髋翻倒；
  * `cross` 后手 -147.62°、`wave` 后臂 +162.08°：动作表是**侧视**语义
    （f/b = 前手/后手、前腿/后腿，靠 x 前后区分），正面立绘的左右是镜像，
    两者语义根本不对齐。
  * 修：写显式 retarget 层（puppet_mapping.json），
    躯干只给 spine 一次并 clamp 到 8°、hips/chest 固定 0、头部反向补偿；
    两臂改由各自 hand 相对站架的**位移幅度**做 0..1 强度；
    腿沿用原始角度差但 clamp 3°。

v2 看图：人形完整但三档几乎一样。两个原因：
  * 双手信号用 `sum(mf,mb)`，jab 单手 80.2 px 也把另一只手抬起来；
  * 抬臂 42/32° 把 A-pose 抬成水平 T-pose（像投降）。
  * 修：双手信号改 `min(mf,mb)/60` 触发（jab 后手不动、cross 前手不动、
    wave 两臂同时小幅），增益砍到 18..24°。

v3 看图：仍偏「双臂张开」。加前推层 —— 只对**正在出拳的那只前臂**
绕肘放大 `1+0.30*t`、向画面中心平移 `26*t px`、上抬 `8*t px`，
模拟 2D 格斗里拳朝镜头伸出的透视；单手增益回调到 22..32°。
最终看图：jab 前手明显变大前伸、cross 后手、wave 双手，人形完整，
无洞/无重影/无悬浮部件。对照板 `three-driver-paths-comparison.png`、
时间线 `player-V4b-motion-timeline.png` 是看图依据。

|---|---|---|---|---|---|
| jab #8 | 0.6685 | 0.0 | 1.2006 | 1.0 | 63.867° |
| cross #12 | 0.0 | 1.0 | 1.0 | 1.3 | 147.62° |

5. GIF 帧数口径订正（一次真红）
======================================================================

判据 `gifs_frames_exact` 初版要求「GIF 帧数 == 源帧数」，实测
`player-V4b-attack-jab.gif` 只有 11 帧而非 14 → 判据红。
先怀疑 `optimize=True`，关掉后**仍是 11 帧**，说明诊断错了。
逐帧读 duration 才定位真因：Pillow 会把像素完全相同的连续帧合并，
并把被合并帧的时长累加到保留帧（jab 出现 120/180ms 的帧）。

实测 9 条 GIF 总播放时长**严格守恒**：

| 档 | 源帧 | 期望时长 | 各路线实测总时长 |
|---|---|---|---|
| jab | 14 | 840 ms | 840 / 840 / 840 ms |
| cross | 22 | 1320 ms | 1320 / 1320 / 1320 ms |
| wave | 36 | 2160 ms | 2160 / 2160 / 2160 ms |

时间曲线没丢，是判据口径写死了帧数。判据改为
`gifs_timeline_conserved`：总时长守恒 + 2 <= 编码帧数 <= 源帧数 +
与 gif_stats.json 自报的 encoded_frames / duration_sum_ms 双算对账。
三路线合计 33 个重复帧被合并，全部有时长补偿。
`make_3d_attack_gifs.py` 的注释已同步订正，不再误导下一轮。

8. 边界 / 故意没做的部分
======================================================================

  * 游戏源码 0 改动；没有把任何 GIF/立绘接进 Godot，没有改 arena.gd/hud.gd。
  * 没有给玩家 V4b 新建带骨架的 .blend：真网格驱动已被证伪，
    再造一份 40 MB 资产只是复现同一个失败，故直接用现成 PBR 正面立绘。
  * puppet 是**2D 图像骨骼重定向**，不是真 3D 蒙皮动画；
    它不能侧视、不能转身、不能做透视正确的出拳。
  * 动作幅度保守：A-pose 底子本身双臂斜张，正面 2D 无法表现「拳朝镜头」，
    只能靠放大前臂 + 抬臂 + 整体前冲暗示。看图结论是「可读但不够像打拳」。
  * 没有重拓扑 / 平滑权重 / 修 2,809 个开放壳；上一轮已证 Blender
    Voxel Proxy + Data Transfer 能给 99.97% 覆盖，但 35° 驱动右臂仍不可见。
  * 没有渲 228 帧全量图集，没有导 glTF / Godot，没有做多视角立绘。
  * `two-driver-paths-comparison.png` / `driver-probe-foe.png` / `make_probe_sheet.py`
    是迭代中间产物，保留作看图证据，不是最终交付；
    最终对照以 `three-driver-paths-comparison.png` 与 `three-routes-impact-frame-overview.png` 为准。
  * 本机没能给 .venv 装上 numpy（pip 下载 12.6 MB 超时），
    puppet 因此写成纯 PIL 实现，不引入新依赖。
