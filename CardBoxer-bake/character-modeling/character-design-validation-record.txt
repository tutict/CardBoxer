================================================================

一、目标与边界
----------------------------------------------------------------
工程师两轮选择：路线 =「先用 SDXL 出角色设定图」；造型方向 =「尼古喵喵」。
「尼古喵喵」= 2026 年那部猫耳兽人番：青绿短发猫耳、红眼、宽大 T 恤 +
长裤、慵懒反套路不卖萌（资料见 WebSearch，非凭印象）。

边界，逐条如实交代：
  * 本轮只定造型，游戏目录 0 字节变更。
  * 造型参考 ≠ 原角色复刻。真做进游戏前必须差异化，避免直接搬 IP。
  * 不画烟：原角色的「烟不离手」是标志，但游戏角色 + 不美化烟草；
    慵懒 / 摆烂 / 不讨好的气质保留。工程师要加，下一轮补。
  * 产出不是游戏精灵。SDXL 设定图只用来定轮廓 / 服装 / 配色语言，
    A（2D 外观层）或 B（Blender 精灵图集）落地另算。

二、现状取证：为什么这一步是「定造型」而不是「改模型」
----------------------------------------------------------------
  * 游戏目录无任何 .blend / .fbx / .glb / .obj 角色资源；只有
    background/arena.png（上一轮接入的擂台背景）。
  * scripts/fighter.gd::_draw() 用 11 关节坐标自绘：
    draw_line / draw_circle / draw_colored_polygon，圆头 + 梯形躯干 +
    线条四肢 + 圆形拳套 + 椭圆脚 + 单点眼睛，约 190 px 高。
  * data/card_motion.json：12 卡 228 帧 + 3 条受击轨（16/30/10 帧）。
    走路 / 待机呼吸 / KO 倒地是程序化的，不在表里。
  * CardBoxer-bake/boxer_rig.py：13 骨解析 IK，只解算关节坐标，
    没有网格 / 材质 / 渲染。
  * Blender 5.2.0 LTS / Python 3.13.13，headless EEVEE 实测真出 PNG
    （128×128 立方体正交探针，16.8s 含启动）→ B 路线技术可行。

六、实测结论：SDXL 压不住「设定表」构图
----------------------------------------------------------------
  * V1 的 negative 已写 multiple panels / collage / character sheet grid /
    turnaround → 仍出服装拆解表。
  * V3 的 positive 明写 "no panels, no callouts, no text"，negative 再加
    design sheet / turnaround / multiple views / detail callouts / infographic
    → 仍出猫耳帽多视图 + 部件小图。
  * 属性绑定也不稳：mint green 从头发跑到 T 恤（V1 出红发绿衣）；
    amber copper boxing gloves 四张都没稳定出来；bright red irises 也没稳。
  * 结论：这是模型行为，不是 prompt bug。不再继续调词撞墙。
    设定表本来就是「角色设定图」的合适形态，直接取其可用部分。

安全与边界（主动处理，不等工程师问）：
  * 按中性全覆盖战斗服出图，不画露肩 / 露腰 / 肚兜 /
    丝袜特写 / 任何性化姿势；negative 词里逐条点名禁掉。
  * 造型参考 ≠ 角色复刻；进游戏前要差异化（IP）。
  * 不画烟、无背景场景、不是游戏精灵。
  * 游戏目录仍是 0 字节变更。

**为什么这个方向比上一个更贴《牌拳》**（判断，不是迎合）：
琉音的招式是抱拳 / 掌击 / **石头剪刀布** / 双环刃，
「客服 → 裁决官」的身份又能对应三回比牌的结算播报。
猫耳娘只是换皮；琉音和「回合制比牌 + 拳击」在动词层对得上。

V5（2 张，负结果，**不要再用这个思路**）：
  为补「拳套 + 护脸」把该属性提到 prompt 最前、反复强调，
  并砍掉其他服装细节词。结果两张都**彻底翻车**：
  V5-01 → 男性中式道服正/侧视图，裸手；
  V5-02 → 男性道服多视图 + 伪文字 + 圆盘线稿。
  黑白配色、双环发髻、拳套全丢。
  **结论：SDXL 上「反复前置强化单一属性 + 删除竞争细节」
  会把语义簇整体推走**（martial arts 与 boxing gloves 冲突时
  模型选了武术道服），比不强化更差。停手，不再撞墙。

**拳套不靠出图**：`fighter.gd::_draw_glove()` 本来就是
`draw_circle` 画圆拳套，A 路线落地时由代码画；设定图只负责
服装 / 配色 / 发型 / 配件语言。所以「四张都没有拳套」不是
阻塞项，别为它再渲一轮。
