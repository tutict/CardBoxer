一、结论（先看这段）
--------------------------------------------------------------------------------
  1. 真正拖观感的不是 P2/P3/P4 修过的数值特征，而是**姿态语义倒挂**：
     P0 规格把最大牌 triple 绑给 wave、最小牌 scatter 绑给 jab，
     但实测前手伸展峰值 wave 1.7224 < cross 18.9248 < jab 44.0145 px。
     最大的牌打出的姿态最弱，最小的牌最强。这是可复算的硬差距。
  2. 第二条硬差距：cross 的伸展峰值落在 windup 第 3 帧，而 active 命中窗
     是第 6–9 帧——「看起来在打的那一帧」和判定帧错位，违反 S3 的
     hit pose / hitbox 对齐原则。
  3. 查证把 KOF / 街霸招牌动作拆成 8 条通用动画原理 + 13 个在 11 关节表上
     可复算的指标，固化成 招牌动作规格.json；不复刻任何具体角色的招式
     造型、名称、特效或帧数。二手资料里的具体帧数只作量级参考。
  4. 发现一条必须先解决的硬冲突：招牌动作要「命中定格」，而 P4 刚把
     255 对精确平台清成 0 并写进 91 条承重判据。规格给出解法：用非零
     微小差异做低速段，exact_hold_pairs 保持 0，不退役不篡改 P4。
  5. 本阶段不评好不好看、不宣称引擎内效果。看图板只用于复核「差距是否
     肉眼可辨」，不是观感结论。

  攻击轨（有 active 段）6 条：cross / jab / sweep / throw / uppercut / wave
  其余 9 条：backstep / block / focus / guard / hit_heavy / hit_light /
             recover / rush / sidestep（受击轨无 phase 字段，统一标 react）

  攻击轨分布
    peak_reach_gain_px   min 1.7224 / q50 21.8228 / max 44.0145
    peak_bbox_gain_pct   min 14.149% / q50 62.9125% / max 83.4387%
    arc_deviation_px     min 0 / q50 10.6388 / max 25.4837
    end_drift_px         min 0 / max 1.2083 @sweep
    stance_width_max_px  min 82.1333 / max 90.4

  差距清单 6 条
    [hard]      L3  cross 峰值 @frame 3 在 windup，active 是 6–9
    [hard]      L2  三档伸展倒挂 1.7224 < 18.9248 < 44.0145
    [note]      L2  wave 剪影仅 +26.2781%
    [note]      L1  cross 蓄力后收 0.0 px
    [conflict]  L4  P4 后精确平台总数 0，hitstop 不能靠整帧相同实现
    [constraint]L5  末帧最大漂移 1.2083 px，pose_probe 红线 1.5 px

  另有三条「全表性」观察：
    · 六条攻击轨 recover_overshoot_px 全为 0 —— 峰值后直接线性回站架，
      完全没有 follow-through。
    · focus（22 帧）与 recover（14 帧）的 peak_reach_gain_px 为 0。
    · 峰值姿态两两距离最小 92.0107（jab|uppercut），最大 615.2215
      （sweep|uppercut），L8 改动后不得低于现有最小值的 80%。

  **口径警告**：pose_metrics.end_drift_px 是「末帧 11 关节逐点欧氏距离
  最大值」，与 P4 验证记录里的 1.100 px 口径不同，两套数字不互相折算、
  不要写成同一个数。这是刻意在规格里写进 caveat 的。

五、踩过的坑（留给下一轮）
--------------------------------------------------------------------------------
  1. verify_pose_spec.py 首版写了 GAP["attack_track_count"]，而
     diag_pose_gap.py 产物里只有 attack_tracks 列表 → KeyError。
     改成 len(GAP["attack_tracks"])，14/14 全绿。
  2. 变异 M3/M14 的 needle 把 JSON 引号一起包进去
     （'"+x forward; -y up"'），实际文件里该子串前面不是引号 → hits 0。
     按纪律记为 DID NOT RUN（不是「通过」），改成裸文本后命中 1 次。
  3. 变异 M12 首版从 JOINTS 删掉 b_foot，守卫子进程崩栈 → BROKEN。
     语法成立不等于运行时成立；换成「改 reach 默认侧为后手」后 CAUGHT。
  4. 汇总口径：DNR 组没有写文件，不该计入 RESTORE 分母。改为
     restored == attempted == len(rows) - dnr，expect_hit == caught。
  5. 图上的 wave 骨架手臂明显抬高，容易误读成「wave 其实动作很大」。
     实际上抬高手臂并未增加 f_hand 到 shoulder 的距离（1.7224 px），
     这正是 reach 指标要抓的东西；终版在骨架旁补了文字说明。
