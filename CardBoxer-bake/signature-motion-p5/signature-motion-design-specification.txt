一、结论（先看这段）
--------------------------------------------------------------------------------
  1. P2/P3/P4 修的都是「数值特征」——幅度上限、方波平台、原生重复帧。
     实机验收已证明它们「没把动作改坏」，但两版差异肉眼很弱。
     P5 要动的是**姿态语义**，不是再调一次数值。
  2. 读盘侦察发现真正的根因，且可复算：
       牌型强度（P0 规格）：triple(最大) → wave / sequence → cross / scatter → jab
       实测前手伸展峰值：  wave 1.7224 px  <  cross 18.9248 px  <  jab 44.0145 px
     **完全倒挂**：最大的牌打出的姿态最弱，最小的牌最强。
     另：cross 的伸展峰值落在 windup 第 3 帧，而 active 是第 6–9 帧，
     命中时手已经收回去了——打击帧与姿态错位（S3 的 hit pose 对齐原则）。
  3. 查证把「拳皇/街霸招牌动作」拆成 8 条通用动画原理 + 13 个在
     11 关节表上可复算的指标，不是照抄任何角色的招式造型或帧数。
  4. 有一处硬冲突必须先点名：招牌动作要求「命中定格」，而 P4 刚把
     255 对精确平台清成 0 并写进 91 条承重判据。解法是**用非零微小
     差异做低速段**，绝不重新引入整帧完全相同的定格，不退役 P4 判据。
  5. 本轮不评「好不好看」。规格成立与否由判据证明；观感结论要等
     #217 引擎内 A/B 与看图环节单独给。

三、提炼出的 8 条姿态语法（每条都绑定可复算指标）
--------------------------------------------------------------------------------
  坐标系 card_motion.json:units = game px / 原点脚下 / +x 向前 / -y 向上。
  所以 hip.y 变大 = 质心下沉；f_hand.x 变小 = 击打手后收。
  全部公式在 pose_metrics.py，13 个指标对 15 轨逐轨可算。

   L1 蓄力预备可读   windup_recoil_px / windup_hip_drop_px
                     起手段必须反向预加载，且深度随 heavy>medium>light 递增。
   L2 命中剪影张开   peak_reach_gain_px / peak_bbox_gain_pct
                     active 峰值手接近伸直、剪影显著大于站架，三档严格递减。
   L3 峰值对齐命中   peak_reach_phase / peak_reach_argmax
                     硬约束：六条攻击轨的 reach 峰值必须落在 active 段。
   L4 命中停顿       impact_hold_len / exact_hold_pairs
                     要视觉停顿，但 exact_hold_pairs 必须保持 0（见第五节 C1）。
   L5 随动过冲       recover_overshoot_px / end_drift_px
                     峰值后先过冲再回落，末帧漂移不破 1.5px 红线。
   L6 重心与接地     foot_ground_max_px / stance_width_max_px
                     下沉与前压联动，脚不浮空，重档站架不缩窄。
   L7 弧线路径       arc_deviation_px
                     击打手不走直线；上勾向上、扫腿向下。
   L8 招式可辨       peak_pose_distance
                     两攻击轨峰值姿态逐点距离之和不得低于现有最小值的 80%。

  阈值策略：规格层只钉公式、方向、约束与依据；具体档位阈值由 #215 对
  当前 6 条攻击轨的分布（q75 等）复算后写进候选评估。不写死会过期的数字。


四、现状实测（全部由脚本复算，不是印象）
--------------------------------------------------------------------------------
  probe_tables.py
    · card_motion.json 12 卡 + 3 受击 = 15 轨；phase 三段式只存在于 6 条
      攻击轨，3 条受击轨没有 phase 字段（诊断里统一标 react，不伪造三段）。
    · 三份表 11 关节逐值核对 6248 个值，分歧 0（P4 同步态仍成立）。
    · stance 包围盒 88 × 172 = 15136 px²。

  diag_pose_gap.py（攻击轨分布）
    · peak_reach_gain_px   min 1.7224 / q50 21.8228 / max 44.0145
    · peak_bbox_gain_pct   min 14.149% / q50 62.9125% / max 83.4387%
    · arc_deviation_px     min 0 / q50 10.6388 / max 25.4837
    · end_drift_px         最大 1.2083 @sweep（pose_probe 红线 1.5）
    · 攻击轨 recover_overshoot_px 全部为 0 —— 峰值之后直接线性回站架，
      完全没有 follow-through。
    · exact_hold_total = 0（P4 落地态）。

  差距清单 6 条，其中 2 条是硬差距：
    [hard] L3 cross：reach 峰值在 windup @frame 3，与命中帧错位
    [hard] L2 wave/cross/jab：三档伸展强度倒挂 1.72 < 18.92 < 44.01
    [note] L2 wave：峰值伸展 1.7224 px，剪影仅 +26.2781%
    [note] L1 cross：蓄力后收 0.0 px
    [conflict]  L4 ALL：精确平台 0，hitstop 不能靠整帧相同实现
    [constraint] L5 sweep：末帧漂移 1.2083 px，接近 1.5px 红线

  **口径警告**：end_drift_px 是「末帧 11 关节逐点欧氏距离最大值」，与 P4
  验证记录里的 1.100 px 口径不同，两套数字不互相折算、不要写成同一个数。


五、冲突与成本账（落地前必须先算的）
--------------------------------------------------------------------------------
  C1 hitstop vs P4 精确平台
     P4 把 255 对精确平台清成 0 并写进 91 条承重判据。招牌动作要的
     「命中定格」若用整帧 11 关节完全相同实现，会把 P4 打回。
     → 解法：非零微小差异的低速段（视觉停顿但数值不全等），
       exact_hold_pairs 保持 0；不退役、不篡改 P4 判据。
  C2 随动过冲 vs pose_probe 1.5px 红线
     → 过冲只放在峰值与 recover 中段，末帧必须回 stance 邻域。
  C3 三表同步
     2D 读 card_motion.json（fighter.gd:1027 → CardMotion.sample），
     3D 读 motion_input*.json（rig_driver.gd::_joints_of）。
     → 任何改动必须三表同帧同值，并用 sha + 逐值对账证明。
  C4 历史守卫债
     P1/P2/B/P3/P4/实机验收的 verify 与 mutation 都钉过动作表 sha 或旧值。
     改 11 关节必然红。→ 按既定约定不篡改历史结论：实测、逐条列红因、
     原字节还原，在验证记录单列「历史守卫债」。
  C5 2D / 3D 可见性分叉
     3D 开态 fighter.gd::_draw() 画完影子即 return，2D 关节表不参与绘制；
     姿态改动在 3D 开态只经 13 骨 delta 可见，默认关才直接改 2D 火柴人。
     → 引擎内 A/B 必须分两态取证。

  成本面：2D 火柴人 / 3D 13 骨 delta / 全量 284 帧真实 GLB 撕裂
  （P4 上界 0.042681m，外部锚 0.09365m）/ pose_probe / 6 套历史判据 /
  P4 的精确平台与可辨平台指标。这一轮比前四轮贵，所以先落规格再动刀。


六、边界（明确不做什么）
--------------------------------------------------------------------------------
  · 不复刻 SNK/Capcom 具体角色的专有招式造型、招式名、特效、帧数与台词；
    只采用通用动画原理（anticipation / impact / follow-through /
    silhouette / arc / hitstop）。
  · 不改玩法判定、卡牌规则、伤害公式、三回制、怒火槽、EX 规则。
  · 不改 reveal 1.5s / resolve 1.9s 阶段时长，不改 tk_phase 状态机。
  · 不改 arena.gd / fighter.gd / rig_driver.gd / card_motion.gd 源码；
    不改 mapping 增益与限幅参数（除非 #215 证明确有必要并另立成本账）。
  · 不改 GLB / .blend / 贴图 / .import，不重烘外部资产。
  · 三份动作表必须同步；不改非关节元数据与序列化格式（沿用 P4 的
    round-trip 恒等证明）。
  · 规格只钉可复算指标，不评好不好看；不宣称任何引擎内效果。
