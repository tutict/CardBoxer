一、结论（先看这段）
--------------------------------------------------------------------------------
  1. 这一轮改的是**姿态语义**，不是 P2/P3/P4 那种数值特征。最终只改
     wave / cross 两个轨的四个手臂关节、共 42 帧；jab 一帧不动。
  2. 两次口径订正都是读盘读出来的，不是事后找补：
     R1 —— #213 用的 reach = |f_hand − shoulder| 被肩部轨迹污染。逐帧实测
           cross 的 f_hand 全程恒为 (44, −156)，只有 shoulder 在动，
           mf = |f_hand − stance.f_hand| 全程 0；wave 的手与肩同步平移，
           reach 几乎不变。主强度指标因此改为 rig_driver.gd 原样使用的 mf。
     R2 —— R1 首版为了凑「三档 mf 严格递减」把 jab 前手按比例收短，
           落地后 reach_probe 报「判定 118 / 画面最远 76 / 隔空命中 42 px」。
           这是**真回归**，不是判据误报。立刻用 apply_pose_p5.py --restore
           逐字节回退三表到 P4 上线态，再否决递减目标：格斗游戏里轻拳的
           「轻」由帧数短、收招快表达，不由手伸多远表达。
  3. R2 落盘实测：mf 峰值 wave 60.823 / cross 36.000 / jab 80.225 px，
     六条攻击轨的 mf 峰值**全部落在 active 段**；端点漂移 0 px、
     精确平台 0、2D 最大关节位移 40.0 px、3D 最大臂骨 delta 18.0617°。
     三表 6248 个关节值逐值同步、分歧 0。
  4. 3D 画面差异肉眼可辨，不是纯数字：wave 峰值帧前手 x 从
     66.000000 推到 104.793852，双臂展开；引擎内同进程 A/B 的 16/16
     改动帧像素差非零，最大 33884 px。stance 与 jab 两个「R2 明确不动」
     的对照帧逐像素差 0，reapplied 与 shipped 逐像素差 0。
  5. 成本如实记账，没有藏：真实 player-rigged.glb 上跑 568 姿态
     （baseline + pose_p5 各 284 帧），p999 边撕裂 0.042681 → 0.047884 m，
     +0.005203 m / +12.19%，越外部锚 0.09365 m 的帧 0，余量 0.045766 m
     ≥ 2× 已耗成本。P4 的「不比基线差过 1mm」阈值不适用姿态重设计，
     改钉「余量 ≥ 2× 已耗成本」，并把成本明写在看板上。
  6. **不冒充完成**：L4 命中停顿仍用非零微差（保持平台 0）、L5 随动
     过冲仍为 0。这两条是已声明边界，不是本轮修好的东西。

九、边界与未修
--------------------------------------------------------------------------------
  · L4 命中停顿：用非零微小差异做低速段，exact_hold_pairs 必须保持 0，
    不退役 P4 结论。本轮没有引入真实 hitstop。
  · L5 随动过冲：recover_overshoot_px 攻击轨仍全为 0。
  · 静态 A/B 是冻结态，不是真实自动对局；P4 实机验收通道的结论
    不因本轮改动作表而自动外推，live_p4 重跑仍 60/60 全绿。
  · 3D 开态 fighter.gd::_draw() 只画影子就 early return，2D 关节表
    不参与绘制，所以「3D 开态的 2D 像素 A/B」前提不成立，改由引擎
    读回 CardMotion._tracks 做数值判据。
  · 跨 Godot 进程整帧逐像素等价不成立（B 路线已证），故三模式 A/B
    全部放在同一进程内。
  · 成本是**真实上升**的（+12.19%），不是「无代价优化」；仍在外锚内。
