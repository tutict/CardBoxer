三、设计决策：为什么不重新绑骨
====================================================================
现状已有 boxer_rig.py / boxer_bake2.py / baked2.json（228 帧、11 关节、逐帧
game px）。若在 Blender 里另起一套骨架再烘，就会出现「两套姿势真相」：
渲染帧与判定帧不同步，动作表一改两边都要对齐。

因此本轮【不绑骨】：让 36 个带厚度的 mesh 部件直接吃 baked2.json 的 11 关节
逐帧坐标，用 set_segment() 把每根肢体按 a_px→b_px 摆位/旋转/缩放。渲染只是
现有动作表的一种「皮肤视图」，动作表仍是唯一真相。

坐标桥（与 boxer_rig.pt 和 fighter.gd::_build_pose 一致）：
    game px : origin at the feet, +x forward, -y UP
    blender : (x, depth, z) = (game_x / 100, layer_depth, -game_y / 100)
    相机 ORTHO, ortho_scale=2.6, 512px, target.x=0.25
    => 196.923 px / blender unit == 1.96923 px / game px

【承重证据】从 stance 的 f_foot.x=36、b_foot.x=-44 推出两脚屏幕跨度
    80 game px / 100 * 196.923 = 157.5 px
    实测最终 stance 图鞋底中心 L=131.0 / R=289.0 => 158.0 px（误差 0.5 px）
这不是「看起来对」，是渲染确实吃游戏关节坐标的硬证据。

   金扣厚底鞋都在，V4-02 的造型语言基本落地

【已知结构缺陷 —— 4 条，八帧对照图里每一帧都有】
 1. 躯干断裂：领口白三角与红腰带之间几乎是空白，white_outer 只是两块小
    矩形，没连成 hip→shoulder 的连续体块。头/领子像浮在腰带上。
 2. 拳套连接弱：橙/青球与袖子之间只有细白条，jab 帧里几乎脱开。
 3. 配件悬空：两侧银色 C 形环刃在腰带旁完全不接触身体；腰下红色
    「中国结」被做成一根向上的粗箭头，更像 UI 指针而不是结饰。
 4. 正面正交下「出拳」读不出来：f_hand 的前后深度被压平，jab 只表现为
    手臂横向张开。要表达纵深得把 z 位移映射成缩放/明暗（假透视），
    或改用 3/4 视角相机。

【判据边界】pose_frames_distinct 只证明「像素变了 / 数据驱动」，**不证明
姿势好看、不证明造型合格**。这两件事必须分开说，否则 10/10 会被误读成
「可以进游戏了」。

====================================================================
八、成本账：为什么不该现在渲 228 帧
====================================================================
 渲染本身不贵：headless EEVEE 单帧约 2s 量级，228 帧大约几分钟。
 但代价不在渲染，在【固化】：现在渲出来的每一张都会带上第七节 4 条断裂，
 后续还要做 alpha 抠底 / 锚点对齐 / 图集打包 / 引擎内换帧。一旦先修造型，
 这批 228 张 + 打包产物全部作废重来。

 所以顺序应当是：修造型（1 轮，4 个 mesh 改动）-> 渲 8 帧复评 -> 再渲全量。
 修法已经明确：
   a) 补一段 hip→shoulder 的连续白色外套体块，连起领口/腰带/髋部
   b) 补 shoulder→elbow→hand 的连续袖子段并加宽连接
   c) 环刃与红结锚定到 hip/shoulder 关节而非世界坐标；红结改真正的结形
   d) 若要纵深感：z 位移 -> 缩放/亮度，或切 3/4 视角（注意会破坏「屏幕 x
      与判定 x 一致」这条正交红利，得重新验坐标桥）

 另一条更省的路：把本轮成果定位为「设定预览 / 结构验证」，游戏内表现继续
 用已落地的 A 路线代码自绘外观层（fighter.gd + fighter_skin.gd），
 2.5D 只做美术方向参考，不进运行时。

====================================================================
九、跨会话的坑
====================================================================
 - 守卫要查【真实对象名】而不是自己维护的 dict key。第一版 _assert_parts()
   假报 missing spec parts: ['platform_shoe']，实际 36 个 mesh 全都在。
 - 面部细节必须在【头球前表面之外】：半径 0.18 * 层厚 0.62 => 前表面
   D_HEAD-0.1116 = -0.1416；D_FACE=-0.085 会被完全遮住。-0.155 才出来。
 - 强环境光会把 Principled 洗白：world 0.75 / SUN 2.4 / fill 320 时，
   INK 0.11 出成中灰、白脸与白躯干糊在一起。深色像素 268 -> 6255 是量化证据。
 - 「字节变了 != 画面变了」本仓第三次：重复帧 sha256 不同，只是 tEXt 的
   Date / RenderTime 不同，IDAT 逐字节相同、像素 bbox=None。
 - RGBA 差分前必须 alpha_composite 到白底。直接用原 RGB 比，透明天空下
   隐藏的 RGB 值会制造假差异或掩盖真差异。
 - ViewImage 首次对最终 stance 图返回 SENSITIVE_CONTENT_UNAVAILABLE；换成
   纯技术性描述查询（色块 / 五官形状 / 过曝）后正常返回，不是图片损坏。
