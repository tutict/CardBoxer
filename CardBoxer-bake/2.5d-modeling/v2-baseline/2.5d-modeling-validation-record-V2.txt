一、结论先行
====================================================================
反馈成立，不辩解。V1 是「12 个独立几何零件按关节坐标摆位」，不是建模，
所以怎么打光都拼不出人样。V2 推倒重做为【连续轮廓体块】：头、脖子、
梯形躯干、两段式手臂、两条独立裤腿、鞋连成一体，八帧全部能读出人形。

复跑 verify_2d5.py 10/10 PASS（MODEL_2D5_VERIFIED），坐标桥仍成立
（鞋距实测 157.0 px vs 预测 157.5 px），游戏目录 0 文件改动。

但要把上限说清楚：这是**风格化几何纸片人**，不是精致角色。它能做到「有人样
、动作可辨」，做不到「好看」。要更好看必须换路线（第七节）。

二、根因：为什么 V1 没有人样
====================================================================
 【上一轮的误判，先订正】我在 V1 记录里写「white_outer 只是两块小矩形，
 躯干断裂」——错的。读代码确认：white_outer 是一条 48 game px 宽、
 68 px 高的真实矩形外套。它看不见是因为 **film_transparent + 白底合成，
 白外套和纯白背景同色**，只剩黑领口和红腰带可见，才像头浮在腰带上。

 真因 1（同色消失）：白色部件没有轮廓。白外套、白袖、白背景三者同色，
   人的视觉拿不到肩线 / 臂线 / 躯干边界。
 真因 2（零件拼贴）：两条腿都从**同一个 hip 点**出发，用等宽椭球拉伸，
   在髋部交叠成一个黑球；手臂同理。球当头、两块白矩形当躯干、两个大黑
   椭圆当腿 —— 这是「零件袋」，不是身体。
 真因 3（配件失控）：环刃完全悬空、红色中国结被做成一根向上的粗箭头、
   拳套直径接近头宽。

 还有一条**本轮自己踩的**：V2 第三轮把单条手臂带加宽后，肩两侧出现两片
 白色「三角翼 / 披风」。我连续猜错两次（先怪 miter 折角，再怪单条带穿 V 形），
 最后靠对象级诊断才定位（第四节）。

三、V2 设计（坐标桥与动作表一行未改）
====================================================================
 不重新绑骨、不重烘：228 帧 baked2.json 的 11 关节仍是唯一真相，
 渲染帧 == 判定帧。坐标桥 (x, depth, z) = (gx/100, layer, -gy/100)，
 ORTHO ortho_scale=2.6 @512px => 1.96923 px / game px。

 核心新增 set_ribbon()：按「中心线点 + 逐点半宽」生成一条**连续挤出带**
 （前面 / 后面 / 左右侧壁 / 两端封盖），每帧重建 mesh 顶点。
 不是球体堆叠。带子是真体积，raking light 会出边。

  - 躯干：hip → 中 → shoulder 的梯形，半宽 [17, 21, 26] game px（腰窄肩宽）
  - 黑马甲：同中心线更窄的深色带，让白外套有可读边界
  - 脖子：shoulder → 下巴，补上 V1 完全缺失的连接
  - 手臂：各自从 shoulder±20 出发，上臂 / 前臂两段 + 袖口
  - 腿：各自从 hip±12 出发（解决并腿黑块），裤管终点伸进鞋里（消白缝）
  - 头：竖向「蛋形」轮廓 ribbon，圆顶 / 颧骨宽 / 下巴收，不再用球
  - 描边：每个部件后方垫一条半宽 +3 game px 的深色 ribbon
          —— 这是修「同色消失」的关键，白外套立刻有轮廓

 保留：12 部件清单、11 关节、8 个 shot、manifest 口径、_assert_parts()
 查真实对象名（不查 dict key）、相机 / 灯光 / 配色语义。

六、视觉评审（V2-5 最终）
====================================================================
 【读得出来】双环发髻 + 红绒球 + 金发夹、半眯眼与嘴、脖子、白外套肩线、
 黑交领马甲、红腰带与中国结、灰色上臂/前臂两段、两只拳套、两条独立裤腿、
 金扣厚底鞋。八帧里 stance / jab / sweep / throw / hit_heavy 姿势可辨，
 enemy 配色与 12° 相机角生效。

 【已知遗留，不粉饰】
  1. 后侧手臂在 stance 里几乎被白外套遮住，只剩一条描边 —— 护头姿势下
     b_hand 的 x 落在躯干宽度内，属关节表姿势的必然结果，不是渲染 bug。
  2. 中国结仍偏像小沙漏 / 蝴蝶结，环刃仍是腰侧悬空的装饰。
  3. 整体是极简几何纸片风：没有手指、没有布料褶皱、没有表情变化。
  4. 正面正交把前后深度压平，jab 只表现为横向张臂（坐标桥红利换来的代价）。

 【判据边界】10/10 只证明数据驱动 / 确定性 / 坐标正确，**不证明好看**。
 这次「像不像人」是靠看图判的，不是靠脚本判的。

七、成本账与下一步
====================================================================
 本轮 5 轮重渲，每轮 8 帧共约 2.6s，总渲染开销可忽略；真正成本是**猜错根因**
 的两轮。教训：形状问题先做对象级隔离渲染，别靠推理连续试参数。

 若要「好看」而不是「有人样」，三条路：
  A. 继续修几何：加手肘/膝盖关节球、布料分块、双层高光、3/4 视角。
     成本中等，上限仍是几何风格；注意 3/4 视角会破坏「屏幕 x == 判定 x」，
     必须重验坐标桥。
  B. 换手绘 / SDXL 出精灵再切片：视觉上限最高，但要重做 228 帧对齐，
     且会重新引入「渲染帧 vs 判定帧」同步问题。
  C. 到此为止：2.5D 只作设定预览，运行时继续用已落地的 A 路线代码自绘
     外观层（fighter.gd + fighter_skin.gd）。成本 0。

 仍不建议现在渲 228 帧图集，除非先选定路线。
