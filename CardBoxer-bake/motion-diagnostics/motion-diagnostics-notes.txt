====================================================================
0. 结论先行
====================================================================

3D 角色现在**大部分时间是站桩**，不是「动作不好看」而是「几乎没有动作」：

| 口径 | 实测 |
|---|---|
| 一回总时长 | 3.4 s（reveal 1.5 + resolve 1.9） |
| 赢家播动作窗口 | 1.12 s（ATTACK_S）= **32.94%** |
| 输家 / 平局 / 亮牌 | **0 s**，全程 `stance` |
| 3D 动作表 | 3 卡 72 帧（jab 14 / cross 22 / wave 36） |
| 2D 动作表 | 12 卡 228 帧 + 3 条受击轨道 56 帧 = 284 帧 |
| 3D 覆盖率 | 72 / 228 = **31.58%**；受击轨道 **0 条** |
| `apply()` 白名单 | 只认 jab / cross / wave，其余全退 `stance` |

`arena.gd::_sync_3d_layer()` 只在 `tk_rhythm_t <= ATTACK_S` 给
`tk_rhythm_winner` 那一侧播帧；源码注释自己写明「73 帧表里没有受击
轨道，硬凑会变成自造动作」。实测表里是 **72 帧**（注释的 73 是口径差）。

====================================================================
1. 三个可分离的缺口
====================================================================

G1 覆盖缺口（最根本）
  `data/motion_input.json` 只有 3 张卡；`card_motion.json` 的另外 9 张
  （uppercut / sweep / rush / backstep / guard / sidestep / focus /
  recover / throw）和 3 条受击轨道（hit_light 16 / hit_heavy 30 /
  block 10）在 3D 侧一条都没有。亮牌阶段 2D 在播 focus，3D 是站架。

G2 时序缺口
  只有赢家在 1.12 s 内动，输家 0 s；平局两侧都 0 s。2D 侧的
  KOF 节奏（前压 / 击退 / HIT! 停顿）只给了 3D 层 `visual_shift` 位移，
  后仰 / 倾角属 2D 绘制层，3D 骨骼不吃。

G3 幅度缺口（"像 A-pose 摆臂" 的量化）
  按 mapping 逐帧复算 13 骨 delta：
    upperarm_f  -21.39..0°   forearm_f -17.38..0°
    upperarm_b   0..28°      forearm_b  0..22°
    spine       -3.07..8°    head      -4.80..1.84°
    四条腿骨    ±3°（`leg_cap_deg=3` 在 57/72 帧里真的削掉了原始角度）
    torso_cap 8° 命中 4 帧
  每个动作**只动一条手臂**：jab 只前手（手部最大位移 80.22 px），
  cross 只后手（前手 22 帧精确 0 px），wave 双手小幅（22.09 px）。
  这不是数据损坏，是 2D 侧动作设计；但 3D 上就显出单臂摆动的僵硬感。

3. 风险（历史负结果，别重复踩）
====================================================================

- `route-c-deformation-v2/C-route-V2-validation-record.txt`：唯一有效的是 x1.5 arm-only
  增益，但同增益下最坏 tear p999 0.05411 m、>5cm 边 186；权重领地
  修正让撕裂恶化 1.894 倍 / 5.4 倍且幅度贡献为 0；平滑只降 5.6%
  （噪声量级）。**放大幅度 = 放大撕裂**，新增/放大的动作必须先做
  小样本幅度-撕裂扫描，不能只调 mapping 就上。
- GLB 是 2,809 连通壳的碎壳模型、0 animations，13 骨 pose 全靠
  GDScript 每帧现算；动作越多不代表越好看，要看逐帧图。
- `F-route-validation-record.txt` 早写明「侧视 2D 动作表重定向到正视 A-pose 有
  固有语义损失」：扩表能补覆盖，补不了这个语义损失。
