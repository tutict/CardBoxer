二、三条被证伪的路线（每条都有硬数据）
------------------------------------------------------------------------
(1) A-pose 权重领地修正 —— 纯度上去了，净效果为负

  做法：Data Transfer 用 POLYINTERP_NEAREST 把 Voxel 代理壳**表面**权重
  贴回 64,024 顶点高模；高模是几千个开放薄壳，手臂顶点掺进 chest/hips
  权重。按 A-pose rest 骨段给每个顶点定 owner 族（arm_f / arm_b /
  torso / leg_f / leg_b），跨族权重乘 ALPHA=0.10、肩髋桥接骨乘
  BETA=0.45，再归一化。

  纯度确实提高（mean own weight，V1 -> V2）：
    arm_f 0.83376 -> 0.89875    arm_b 0.83599 -> 0.90144
    leg_f 0.83840 -> 0.91545    leg_b 0.84071 -> 0.91387
    torso 0.56479 -> 0.72812
  但 72 帧逐帧手腕簇位移：
    V1_base mean 0.17448 m  /  V2_base mean 0.17448 m
    **weight_only_at_x1 = 1.0000**，幅度贡献为零。
  同增益 x1.5 公平对照（剔除增益影响）：
    V1_gain 最坏 tear p999 0.05411 m、>5cm 边 186
    V2_final 最坏 tear p999 0.10248 m、>5cm 边 1007
    **撕裂恶化 1.894 倍 / 5.4 倍**。根因是跨族权重被硬切，肩髋接缝
    的权重梯度变陡，相邻顶点位移差变大。
  判据 V2-13 / V2-14 / V2-15 把「纯度提高、幅度为零、撕裂恶化」三件事
  同时钉住，防止后来者把这个已经否掉的方案重新捡起来。
  证据保留：territory_probe.json / territory_metrics.json /
  frames/{jab07,cross11,wave18}-{V1,V2}.png。

(2) 按连通分量清理游离碎片 —— 删碎片等于删掉整个人

  C 路线验证记录写「没修生成模型自带的 2,809 壳与腰间游离碎片」。
  probe_shells.py 做 union-find 实测：
    总壳 2,809；<200 顶点的小壳 2,799 个，占 **93.46% 顶点**
    （59,837 / 64,024）；最大壳只有 1,134 顶点；top5 壳覆盖率极低。
  frames/shells-small-only.png 只保留小壳的隔离渲染里**整个人形都在**，
  腰间斜片、下摆锯齿也还在。这不是「主体 + 少量碎片」，是 AI 生成模型
  把人拆成几千片拼起来的。按壳大小剔除碎片会把角色删光，此路不通。
  判据 V2-16 钉住「小壳包住身体」这个事实。

(3) 权重邻域平滑 —— 改善在噪声级别

  既然硬切梯度导致撕裂，反向做 Laplacian 权重平滑应该压低梯度。
  probe_smooth.py 扫 5 组 (lam, iters) × 3 代表帧 × 2 增益：
    lam=0,iters=0（基线） tear_gain_mean 0.03656 / reach 0.55084
    lam=0.25,it=1        0.03533 / 0.55084
    lam=0.50,it=1        0.03848 / 0.55084
    lam=0.50,it=2        0.03678 / 0.55083
    lam=0.75,it=2        0.03453 / 0.55083   <- 最好，只降 5.6%
  幅度纹丝不动，撕裂最好只降 5.6%（实验噪声量级），没有采用价值。
  判据 V2-17 要求所有非零 lam 组「撕裂改善 <10% 且幅度变化 <1%」。

三、真正成立并定稿的改动：全帧 x1.5 arm-only 增益
------------------------------------------------------------------------
C 路线增益 sweep 看图给出可用区间 x1.0..x1.5，推荐只调 arm_gain_deg；
但它只在 3 个命中帧上量过。本轮对 jab 14 + cross 22 + wave 36 = 72 帧
逐帧做四组单变量对照（同一骨架 / 同一相机 / 同一份 C 路线原始平滑权重）：

  组            reach_mean  reach_max   tear_p999_max  >5cm_max  foot_gap  penetration
  V1_base       0.17448     0.50489     0.04000        103       0.02301   0.0
  V1_gain       0.25326     0.75003     0.05411        186       0.02301   0.0  <- 定稿
  V2_base       0.17448     0.50489     0.07023        565       0.02301   0.0
  V2_final      0.25326     0.75003     0.10248        1007      0.02301   0.0

  · 幅度倍率 1.4515（V1_gain / V1_base，逐帧 rows 与汇总表双算一致）；
  · **72/72 帧**幅度不低于 x1.0 基线，没有一帧倒退；
  · 脚底贴地偏差恒定 0.02301 m（站架就有，增益不加剧），全帧 0 穿模；
  · 撕裂最坏 0.05411 m，只有 C 路线**刚性基线 0.28048 m 的 19.3%**；
    代价是相对 x1.0 基线的 1.35 倍，判据 V2-11 显式钉住这个代价，不藏。
  · 65/72 帧有 >60,000 顶点位移 >1mm；其余 7 帧是站架/前摇/收招，
    本来就不动，不算把动画关掉。

  定稿配置 = 原 C 路线平滑权重 + arm_gain_deg × 1.5（torso / leg 不动）。
  V2-final-comparison-board.png 的三行两列只变这一个变量，图上伸臂差异可读：
    jab #08   reach 0.4117 -> 0.5724 m
    cross #12 reach 0.4917 -> 0.7340 m
    wave #19  reach 0.2256 -> 0.3405 m

     本来就是站架（关键帧板 reach=0.0000），改用「活跃帧数 >=30 +
     峰值 >60000」，实测 65/72。这是判据口径错，不是数据坏。
  3. mutation_c2.py 的 restore 用文件名字典记，9 个用例改 6 个文件，
     汇总假报 RESTORE=6/9 + MUTATION_C2_FAILED。改成按用例计数，
     真跑 9/9。汇总错了比没有汇总更坏，单列一条。
  4. --probe 的 55° 侧视图沿用循环最后一帧 pose（wave#35），名字却写
     stance。修为渲前显式 pose 回站架，判据 V2-22 钉住这个调用形态。
  5. V2-keyframe-board.png 第三行说明文字被第一排卡片圆角框盖住半截，
     head 104 -> 126 -> 148，两次看图复核后留足间距。
  6. Python 是 Windows 版，不认 /c/... 绝对路径；本轮一律 cd 到工作区
     后用相对文件名，或脚本内写 Windows 路径。
